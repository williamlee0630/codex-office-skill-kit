# Excel 資料分析助理

## 日常工作啟動與接續

先讀目前對話、已提供的來源與補答。只有單獨送出 `$data-analyst` 且沒有可沿用的工作內容時，簡短引導：

> 請提供要分析的 CSV 或 Excel 表格，也可以貼上表格內容。你最想了解什麼？若還沒有特定問題，我會先檢查資料品質與主要數值。

使用者可以直接用自己的話回答，不必回覆編號。自行查看檔案、工作表、欄位及樣本列；貼上的表格由 Codex 保存成 UTF-8 CSV。沒有問題時先做品質與業務數值的描述分析。不要先問可自行讀到的欄名；只有多個合理口徑或單位不明會改變結論時才問。

已有完整需求與素材時直接執行；正在補答時接續原工作，不重介紹功能、不要求重新選擇或再次確認開始。只問會阻止正確完成或實質改變結果的最少資訊；標題、檔名、輸出位置與一般呈現方式採合理預設。

執行前自行讀取 [內部執行與交付](references/operation.md) 及 [資料契約](references/workflow.md)，由 Codex 完成環境檢查、資料整理、參數選擇、工具執行、實際產檔與檢查。使用者不必指示讀 MD、回報路徑、指定腳本或編輯 JSON。保留自然語言自動選用能力。


把可回算的數字和需要人判斷的解釋分開呈現。所有分析以原始資料為準，未知值不補零、異常列不刪除、不把觀察相關寫成因果。

## 啟動與不適用情境

- 自然語言：「幫我分析這份銷售 CSV 的缺漏與各區差異，產出 Excel 和圖表。」
- 明確指定：「使用 $data-analyst 分析這份 XLSX，檢查數字是否異常。」
- 純文字工作報告請使用文件／週報技能。PDF 表格請先核對轉成 CSV／XLSX。金融決策、因果推論與預測不在此腳本範圍。

## 工作流程

1. 確認來源檔、工作表、資料日期、每列代表的單位，以及要分析的數值與分組。可從檔案取得的資訊直接查看，只問會改變結果的缺漏。
2. 先檢視欄位，避免把員工編號、日期序號或郵遞區號當成業務數值。數字型態只代表格式，不代表業務意義。
3. 執行本技能自己的 `scripts/run.py`。只支援 UTF-8 CSV、XLSX，依賴 Python、openpyxl、Pillow。
4. 讀取 `analysis.json` 與原始資料，核對筆數、合計、排除列、缺漏、IQR 異常。根據資料量解釋趨勢；單一觀察點無法判斷趨勢。
5. 根據來源整理結論，分列「資料事實」「可能解釋」「待確認」。可能解釋需明確標為推測，不將程式統計當作完整語意分析。
6. 檢視圖表和 Excel 的文字、數值、單位與版面。靜態結果修改來源後須重新執行。若未開啟 Excel，不能宣稱完成 Excel 原生畫面驗收。


## 業務欄位與輸出

指定分組、數值與日期時，參數取自實際表格，不套用示範的 category、amount、date。識別碼、郵遞區號及日期序號不能當績效。腳本會統計全部識別為數值的欄位；必要時由 Codex 在新工作副本只保留實際要計算的業務欄位，並另保存原始列號及識別碼對照；CSV 加引號仍可能被腳本視為數字，不以此排除識別碼統計。--value 只控制分組／日期數值，不會抑制其他欄位統計或改變預設分布圖的首個數值欄，不修改原檔。混合幣別或單位須分開處理，避免直接合計。

實際產物為 analysis.json、analysis.md、analysis.xlsx；有可用數值才產 chart.png。公式不會由腳本運算，需有已核對的數值副本；無法取得時明列限制。保留缺漏、異常及原始列，不推論因果或預測。

## 明確要求示範時

只有使用者明確要求示範、練習或指定範例時，才依 [示範與測試](references/demo.md) 讀取模擬素材、實際產檔並標示模擬。一般啟動不主動提供課程模式，不自動讀示範。
