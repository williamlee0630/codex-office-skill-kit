# AI 創意企劃助理

## 日常工作啟動與接續

先讀目前對話、已提供的來源與補答。只有單獨送出 `$idea-generator` 且沒有可沿用的工作內容時，簡短引導：

> 你想解決什麼工作問題，或達成什麼目標？有已知限制也可以一起說，我會提出方案並比較做法。

使用者可以直接用自己的話回答，不必回覆編號。問題與目標可用一句日常語言提供，不必有附件。預算、人名、日期未定可先用規劃假設並標待驗證。預設十案；未選案就先交付比較與推薦，不阻擋全部成果。收到選案補答後沿用方案，接續產出執行計畫。

已有完整需求與素材時直接執行；正在補答時接續原工作，不重介紹功能、不要求重新選擇或再次確認開始。只問會阻止正確完成或實質改變結果的最少資訊；標題、檔名、輸出位置與一般呈現方式採合理預設。

執行前自行讀取 [內部執行與交付](references/operation.md) 及 [資料契約](references/workflow.md)，由 Codex 完成環境檢查、資料整理、參數選擇、工具執行、實際產檔與檢查。使用者不必指示讀 MD、回報路徑、指定腳本或編輯 JSON。保留自然語言自動選用能力。


適用：有問題與目標的創意發想。沿用已知目標、限制與成功判準；預算、負責人或日期不足明列待確認，不用範例替代真實要求。

## 工作流程

1. 讀取原始 TXT、Markdown 或 DOCX。需擷取文字時執行 `python scripts/_office.py extract "<原始檔>" --output "<文字檔>"`；不可讀就說明限制，不猜內容。
2. 由 Codex 產生十個做法有實質差異的方案，再檢查換名但內容重複的方案。使用者另指定數量時調整 target_count。成本、難度與價值均標規劃假設及主觀評估，不冒稱真實報價、研究或成效。只為已選定 selected_id 建立計畫；未選時可建議，selected_id 留 null。計畫人名及日期須有依據或明寫為建議並待確認。
3. 讀 [輸入契約與驗收](references/workflow.md)，由 Codex 依原始資料建立有來源 JSON；核對語意後再交腳本驗證欄位及產檔。
4. 執行 `python scripts/run.py --input "<證據 JSON>" --output "<指定輸出資料夾>"`。腳本不進行語意理解、不連網、不執行外部發布。
5. 開啟 Markdown 方案、CSV 比較表與選定方案計畫，核對來源、日期與未知欄位，確認主觀評估有標示；程式測試與 Codex 觸發驗收分開回報。

## 明確要求示範時

只有使用者明確要求示範、練習或指定範例時，才依 [示範與測試](references/demo.md) 讀取模擬素材、實際產檔並標示模擬。一般啟動不主動提供課程模式，不自動讀示範。
