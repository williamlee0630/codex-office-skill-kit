# 簡報輸入契約與驗收

本文件的操作情境均為模擬教學。

## 原始文件到 JSON

腳本不摘要文件。Codex 先讀 TXT／MD，或用 `python scripts/_office.py extract <DOCX或文字PDF> --output <TXT>` 擷取，再依來源產生 deck JSON。每頁只保留原文可支持的事實，把提議與未知直接標示。每頁來源應標明文件及段落，數字保留單位與期間。

必填 `title`、`source` 與 1 至 60 筆 `slides`。每筆必填 `title`、`bullets`；可選 `notes`、`source`。整份可選 `subtitle`、`date`、`simulation`。日期未提供寫「未提供，待確認」，不以執行日冒充資料日。notes 未提供寫待確認，不杜撰發言。

## 字量與頁面

- 16:9，封面另加一頁。指定總頁數時包含封面。
- 封面 44pt、內容標題 32pt、內文 24pt，使用微軟正黑體。其他系統可能替換字型，須視覺檢查。
- 每頁 1 至 5 個重點。半形字計 1、全形字計 2：封面標題最多 72，頁面標題最多 54，每點最多 84，每頁合計最多 260。不接受內嵌換行。
- 超量時非零結束，說明頁碼與拆頁方式。不自動截斷、不擅自省略限制或縮小字體。
- 另以保守斷行與段落間距估算內文高度，超過260pt會要求拆頁；因此即使總字量合格，多個較長段落仍可能被拒絕。
- 字量規則是保守預防，不是文字實際渲染結果。程式檢查物件是否在畫布內，不能證明字型與斷行沒有溢出。

## 實際產物

`presentation.pptx`：可編輯文字、內嵌 notes。寫入後用 python-pptx 重新開啟，確認頁數與備註存在。

`speaker-notes.md`：備註、來源、日期、模擬標示與待人工核對事項。

`layout-check.json`：結構、頁數、邊界、notes 檢查；`visual_review_completed` 固定為 false，只有實際渲染後另行記錄視覺驗收，不能以結構檢查冒充。

## 驗收

1. 核對來源與頁數。模擬例 `deck.json` 為 3 頁內容加封面，共 4 頁。
2. 用 PowerPoint／可用渲染工具逐頁查看，確認標題、斷行、底部頁碼與來源說明沒有遮擋。檢視 notes，核對講稿與原文一致。
3. 調整過長原文時保留所有重要條件及未知，不把尚待確認事項變成已完成成果。
4. Codex 自然語言觸發測試須從 `source.md` 開始、由 Codex 產生 JSON 再產檔，不能以預先整理的 `deck.json` 冒充。
5. unittest 只代表腳本產物與安全行為，不代表技能選擇或原生 PowerPoint 視覺驗收。

無網路、寄信、發布行為。只使用輸入資料，不自動下載插圖，未提供的來源不補造。
