# 發票與收據整理助理

## 日常工作啟動與接續

先讀目前對話、已提供的來源與補答。只有單獨送出 `$receipt-organizer` 且沒有可沿用的工作內容時，簡短引導：

> 請上傳收據或憑證，也可以提供可讀的 PDF、圖片或報帳明細。我會核對欄位、分幣別合計，整理成 Excel。

使用者可以直接用自己的話回答，不必回覆編號。先檢視可讀來源，清楚的欄位由 Codex 自行核對及轉錄；只問看不清楚的特定欄位與單據。不要求使用者填轉錄 JSON。部分模糊仍可產含待確認欄位的明細，有效金額與幣別才納入合計；中間轉錄模板不是已完成報帳 Excel。

已有完整需求與素材時直接執行；正在補答時接續原工作，不重介紹功能、不要求重新選擇或再次確認開始。只問會阻止正確完成或實質改變結果的最少資訊；標題、檔名、輸出位置與一般呈現方式採合理預設。

執行前自行讀取 [內部執行與交付](references/operation.md) 及 [資料契約](references/workflow.md)，由 Codex 完成環境檢查、資料整理、參數選擇、工具執行、實際產檔與檢查。使用者不必指示讀 MD、回報路徑、指定腳本或編輯 JSON。保留自然語言自動選用能力。


先保存辨識依據，再整理金額。看不清楚的欄位保持未知，疑似重複不直接刪除，不把不同幣別相加。

## 啟動與不適用情境

- 自然語言：「幫我整理這批收據，標出看不清楚和可能重複的資料，產出報帳 Excel。」
- 明確指定：「使用 $receipt-organizer 整理這批憑證，依幣別合計。」
- 本技能不提交報帳、不判定可抵稅、不換匯。不確定用途或類別須待人工確認。

## PDF／影像流程

1. 先執行本技能 `scripts/run.py`，腳本檢查 pypdf、Pillow、tesseract、pdftoppm 是否可用。文字型 PDF 可抽取原文，圖片只檢查格式與尺寸；此腳本不自動執行 OCR。
2. 原始檔複製至輸出 `originals/`，SHA-256、工具清單、PDF 頁碼文字保存在 `extraction-evidence.json`。
3. Codex 使用實際可用的視覺工具檢視影像，由 Codex 自行轉錄清楚欄位，只詢問無法辨識的具體欄位。若沒有視覺／OCR 能力，清楚說明限制，不假裝已辨識。
4. 由 Codex 核對並填妥內部 `transcription-template.json`。日期、店家、品項、金額、幣別、類別逐一核對；證據填來源頁碼／區域與可辨識原文。模糊欄位填 null，分類由 Codex 依品項或使用者確認，不依店名武斷推測。
5. 保留原始影像和辨識證據，再以確認後 JSON 為輸入，產生報帳 Excel。PDF／圖片第一次處理不會產生虛假的報帳明細。

## JSON／CSV 流程

1. 先核對來源及資料日期。每筆使用唯一 id，未提供則以內部列號識別，不補造外部單據號碼。
2. 執行腳本，讀取 `receipts-summary.json` 的缺漏、格式與疑似重複標記。
3. 核對各幣含重複合計與暫排除疑似重複合計。兩者都是檢核用結果，是否排除由人決定，所有明細均保留。
4. 逐筆與原始收據比對。沒有有效金額或幣別的記錄不納入合計，必須在人工確認清單中顯示。
5. 檢查 Excel 畫面、欄位與單位。靜態結果修改來源後需重新執行，不能宣稱自動連動。

## 明確要求示範時

只有使用者明確要求示範、練習或指定範例時，才依 [示範與測試](references/demo.md) 讀取模擬素材、實際產檔並標示模擬。一般啟動不主動提供課程模式，不自動讀示範。
