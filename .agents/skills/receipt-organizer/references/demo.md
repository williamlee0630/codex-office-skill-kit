# 收據辨識證據與計算契約

本文件的操作情境均為模擬教學；範例收據不是合法報帳憑證。

## 抽取與人工確認

工具檢查只記錄目前是否有 pypdf、Pillow、tesseract、pdftoppm。腳本只抽取文字型 PDF 與檢查影像，不執行 OCR；可用 OCR 工具不代表已使用。PDF 頁面原文、工具路徑、原始檔路徑與 SHA-256 都留在 `extraction-evidence.json`。空白或掃描 PDF 必須由可用視覺工具或人工轉錄，未知值保留 null。

PNG／PDF／CSV 模擬演練須加 `--simulation`，不依檔名推測。JSON 可用 `simulation: true` 標示；原始單據不能隨意標成模擬。

影像／PDF 不直接產報帳 Excel，先產 `transcription-template.json`。每欄都應能追溯到頁碼／區域／原文。Codex 決定資料語意與類別，腳本不從關鍵字或店名假裝辨識。確認後另存 JSON，再執行一次報帳流程。

若輸出目錄已有報帳 Excel，影像處理明確拒絕，請用新目錄，避免誤把舊成果當新辨識。相同 originals 檔名但內容不同時也明確拒絕，不覆寫證據。

## 可解析資料

JSON：`source` 非空，`receipts` 非空陣列，可選 `simulation` 布林值。每筆欄位 `id,date,vendor,items,amount,currency,category,evidence`。CSV 以這些英文欄名輸入，UTF-8 編碼；來源為 CSV 檔名。

- id 缺漏時使用內部 row-N 列號，不能當作外部收據號碼；同一輸入 id 不可重複。
- date 未提供保留 null，格式不符合 YYYY-MM-DD 標記人工確認。
- amount 使用 Decimal 計算，最多兩位小數，未知填 null。NaN／無限值／負數／超額／額外精度明確拒絕。退款或特殊幣別精度不在本工具範圍。
- currency 為三碼英文字母，轉大寫；未提供或格式不符不納入合計，沒有換匯功能。三碼格式正確不代表幣別已核實，仍需比對原始單據。
- category 由輸入提供，例如交通、餐飲、辦公用品、住宿、其他。未提供列待人工確認，不由店名猜測。
- evidence 是必要的追溯資訊，未提供也保留該筆並標待確認。

## 統計與疑似重複

只有有效金額與幣別納入各幣合計。相同日期、店家、品項、金額、幣別，且鍵值完整時標記疑似重複；不刪除任何一筆，不能認定同額交易必為重複報帳。

報表並列「含疑似重複合計」與「暫排除疑似重複合計」。分類統計包含所有有金額及幣別的記錄，疑似重複也納入，欄名清楚標明。日期、店家或證據未核對的金額仍可能在含重複合計中，故合計不是核准報帳金額。

Excel 所有外來文字使用安全儲存，公式字串不會執行。計算為靜態數值，修改來源後重新產出。原始檔保存於 originals，原始影像的完整檢核責任保留。

## 驗收分層

1. unittest 核對不同幣別不混加、Decimal 合計、疑似重複仍留、未知欄位、非有限金額拒絕、原始證據保留、安全 Excel、影像不冒稱 OCR。
2. 開啟模擬 PNG／PDF，逐欄和轉錄值核對。報帳 Excel 開啟確認單位、欄寬、數字與分類。
3. Codex 觸發驗收必須從原始收據開始，實際讀取並根據可見證據轉錄，記錄看不清楚的欄位。只用預填 JSON 跑腳本不能算 OCR 或語意觸發通過。
