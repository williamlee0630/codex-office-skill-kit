# Codex 開發任務：繁體中文 AI 辦公室 Skill 工具包

## 一、專案目標

請在目前開啟的 `codex-office-skill-kit` 工作區內，從零建立一套完整的「繁體中文 AI 辦公室 Skill 工具包」。

本專案以 **OpenAI Codex 為唯一指定執行環境**，不需要 OpenClaw、飛書、Claude Code 或中國平台的整合。

最終必須完成：

1. 10 個可以在 Codex 中使用的獨立 Skill。
2. 每個 Skill 都有正式的 `SKILL.md`、必要資源、使用範例及測試。
3. 一套繁體中文的電子講義網站，教導沒有程式背景的員工安裝與使用。
4. 完整的模擬工作資料，讓使用者不必準備真實公司的機密文件就能練習。
5. 可供發放學員的 Skill 工具包 ZIP。
6. 開發、測試、安裝及驗收說明。

請實際建立檔案、執行測試、修復問題，不要只提供規劃、偽程式碼或空白模板。

## 二、開發原則

- 所有面向使用者的內容使用台灣繁體中文。
- 以 Windows 與 Codex 桌面版使用者為主要對象。
- Skill 名稱、資料夾及程式識別字使用英文，講義與操作說明使用繁體中文。
- 優先採用 Codex 官方 Skill 規範，正確使用 YAML frontmatter、`name`、`description` 與 `SKILL.md`。
- 每個 Skill 應能獨立啟動與執行，不必先執行其他 Skill。
- Skill 需要支援自然語言觸發，也應能讓使用者明確指定 Skill。
- 儘量降低對額外服務與 API 的依賴。
- 不要將普通 Prompt 包裝成 Skill 就宣稱完成。
- 不要使用假資料冒充真實分析或真實搜尋結果。
- 不要複製外部書籍內容，請自行設計完整的工作流程與模板。
- 不要修改此工作區以外的專案。
- 不要擅自部署、推送 GitHub、寄送郵件或執行其他外部發布行為。

優先使用現有的 `$skill-creator` 輔助建立與驗證。如果目前環境沒有這項 Skill，請依 Codex 官方規範建立，並記錄差異。

## 三、開發的 10 個 Skill

### 01. email-assistant｜智慧郵件處理助理

功能：

- 讀取使用者提供的電子郵件內容或匯出檔案。
- 整理寄件人、主旨、重要事項及截止時間。
- 按照工作重要性分類。
- 識別需要回覆、需要執行與僅供參考的郵件。
- 產生正式、友善、簡潔等不同語氣的回覆草稿。
- 產生每日郵件待辦摘要。

如 Codex 已具備可用的 Gmail 工具，則可支援授權後讀取；否則使用本機郵件檔案，不能假裝已經取得 Gmail 資料。

預設不得自動寄信。

### 02. meeting-assistant｜會議紀錄整理助理

功能：

- 讀取 TXT、Markdown、DOCX 等支援的會議記錄。
- 自動整理會議主題、重點、決議與待辦。
- 擷取負責人、期限、未解決問題。
- 區分提議、討論中、已確認與待確認事項。
- 產生可供主管閱讀的正式會議紀錄。
- 不得將沒有明確定案的內容視為已確認決議。

### 03. project-tracker｜專案進度追蹤助理

功能：

- 接收專案待辦、會議紀錄與工作更新。
- 整合專案最新進度。
- 找出完成、進行中、逾期與有風險的工作。
- 識別前後決策變更。
- 產生專案進度表與風險摘要。
- 支援輸出 Markdown、CSV 或 Excel。

不應自行推測未提供的負責人及完成日期。

### 04. weekly-report｜智慧週報生成器

功能：

- 將零散工作紀錄整理成正式週報。
- 使用 STAR 方法分析工作成果，必要時調整成適合主管閱讀的表達。
- 彙整本週完成事項、進度、成果、遇到的問題。
- 整理下週計畫與需要主管協助的事項。
- 提供精簡版與詳細版。
- 支援 Markdown 或 Word 輸出。

不得編造績效數字。

### 05. receipt-organizer｜發票與收據整理助理

功能：

- 讀取 PDF、圖片及可解析的收據資料。
- 擷取日期、店家、品項、總金額與幣別。
- 按交通、餐飲、辦公用品等類別整理。
- 辨識重複項目及資訊不完整的收據。
- 產生 Excel 報帳明細與金額統計。

無法準確辨識的欄位須標記為待人工確認，不可猜測。

若需要 OCR，請檢查可用工具並提供合理的替代方案。

### 06. presentation-maker｜AI 簡報製作助理

功能：

- 根據文件、工作報告或主題製作簡報。
- 自動規劃簡報架構、每頁標題及重點。
- 按商務簡報原則安排資訊層級。
- 使用可用的程式工具產生實際 PowerPoint（PPTX）檔案。
- 提供講者備註或講稿。
- 檢查頁面是否有文字溢出與版面問題。

不能只產生簡報大綱就算完成。

### 07. document-writer｜商務文件撰寫助理

功能：

- 製作企劃書、提案、商務信函、工作報告。
- 修正文法、段落結構及專業用語。
- 提供正式、精簡、易讀等不同版本。
- 支援既有文件改寫。
- 視工作類型產生 Markdown 或 DOCX 文件。
- 保留原始事實，不隨意加入沒有依據的數據。

### 08. data-analyst｜Excel 資料分析助理

功能：

- 讀取 CSV、XLSX 等工作資料。
- 檢查欄位型態、缺失值與異常資料。
- 自動產生描述統計。
- 根據資料型態選擇適當的圖表。
- 找出有意義的趨勢與異常。
- 產生分析結果、圖表及 Excel 或 Markdown 報告。

使用 Python 執行真正的計算。

區分資料可支持的事實與推測，避免將相關性誤寫成因果關係。

### 09. idea-generator｜AI 創意企劃助理

功能：

- 根據使用者提供的問題、目標及限制提出方案。
- 預設產生 10 個具體且不同的創意方向。
- 評估所需資源、難度、成本及預期價值。
- 比較優缺點並提供建議。
- 為選定方案產生可執行的工作計畫。
- 不可將主觀評估分數表述為已驗證的客觀數據。

### 10. research-assistant｜資料研究與調查助理

功能：

- 根據研究問題規劃調查方向。
- 讀取使用者提供的參考文件。
- 在具備網路工具時搜尋公開資訊。
- 比較不同來源與觀點。
- 識別可信來源、過時資訊及資訊缺口。
- 產生附來源清單的調查報告。
- 標明資料日期及不確定性。

若無法連網，必須提供以現有檔案為基礎的研究結果，不可編造來源。

## 四、資料夾結構

請以目前的專案根目錄為基準建立以下結構：

- `AGENTS.md`：專案共同開發與維護規則
- `README.md`：整套工具包介紹與快速開始
- `.agents/skills/`：10 個真正的 Codex Skill
- `examples/`：各 Skill 的模擬工作資料
- `tests/`：自動化測試與驗收案例
- `handbook/`：完整繁體中文電子講義網站
- `docs/`：技術文件與安裝說明
- `dist/`：可供學員下載的發行檔案

每個 Skill 至少需要：

- 符合規範的 `SKILL.md`
- 明確的啟動情境和非適用情境
- 工作流程與輸入、輸出規則
- 缺少資料時的處理方式
- 至少一份完整使用範例
- 可驗證的測試案例

依需要增加 `scripts/`、`references/`、`assets/`，不要為了形式建立沒有用途的資料夾。

## 五、製作完整繁體中文電子講義

講義形式為可在瀏覽器閱讀的靜態 HTML 網站。

請參考現代線上技術教學文件的設計方式，自行建立原創介面，不依賴外部網站才能正常瀏覽。

### 講義主要架構

**首頁**

- 課程名稱與學習目標
- Skill 是什麼
- Skill 和一般 Prompt 的差異
- 10 個 Skill 的功能介紹
- 建議學習順序
- 下載工具包及開始學習入口

**第 1 章：Codex Skill 基礎入門**

- 認識 Codex
- 認識 `SKILL.md`
- Skill 的啟動方式
- 安裝與驗證
- 學員操作前的準備

**第 2～11 章：10 個 Skill 實際教學**

每一章包含：

1. 這個 Skill 解決什麼工作問題。
2. 哪些員工適合使用。
3. 所需資料與準備步驟。
4. 如何在 Codex 中啟動。
5. 可以直接複製的操作提示詞。
6. 完整操作步驟。
7. 學員使用模擬資料進行實作。
8. 正確的預期輸出範例。
9. 常見錯誤與解決方式。
10. 延伸練習與驗收清單。

**第 12 章：建立與修改自己的 Skill**

- 如何閱讀 `SKILL.md`
- 如何調整觸發條件及工作流程
- 如何加入新的輸出格式
- 如何讓 Codex 協助修改 Skill
- 修改後如何測試
- Skill 使用時的資料安全觀念

**附錄**

- 10 支 Skill 的安裝入口與檔案位置
- 模擬資料下載
- 常見問題
- 基本疑難排解
- Skill 版本紀錄

### 講義設計要求

- 全站使用繁體中文。
- 支援桌面與手機瀏覽。
- 左側章節導覽、主要內容閱讀區。
- 重要操作步驟清晰呈現。
- 提示詞提供一鍵複製功能。
- 程式碼可複製，排版方便閱讀。
- 提供上一章、下一章導覽。
- 不使用無法驗證的操作畫面或虛構截圖。
- 不要寫出過時或未確認的 Codex 操作說明。
- 每一章都要能讓非工程師依照講義完成實作。

## 六、模擬資料與實作驗收

請為 10 個 Skill 各自建立至少一個可實際執行的示範情境。

使用模擬公司、員工、業務數據、郵件與收據資料，不使用任何真實個資。

請讓每份示範資料與講義中的操作流程一致。

每個 Skill 至少測試：

1. 正常資料輸入。
2. 不完整資料輸入。
3. 錯誤格式或不支援輸入。
4. 能否產生所宣稱的實際成果。
5. 是否符合內容與安全規則。

請區分程式自動化測試和實際 Codex Skill 觸發測試，不能用前者假裝完成後者。

## 七、開發順序

請採分階段實作，並在每階段完成後執行測試。

第一階段：建立專案架構、共同規範、測試機制與基本講義框架。

第二階段：完成五個基礎 Skill：

- meeting-assistant
- project-tracker
- weekly-report
- document-writer
- idea-generator

第三階段：完成三個檔案處理 Skill：

- data-analyst
- presentation-maker
- receipt-organizer

第四階段：完成兩個資訊處理 Skill：

- email-assistant
- research-assistant

第五階段：完成所有講義內容、模擬資料、安裝教學、測試與發行包。

請在 `docs/PROGRESS.md` 記錄完成項目、測試結果、尚未完成的功能及下一步。

## 八、品質與驗收標準

請確保：

- 10 個 Skill 的 `SKILL.md` 都符合 Codex 規範。
- 名稱與 description 不互相混淆，能可靠地選擇對應 Skill。
- 所有內部檔案路徑正確。
- 必要的程式腳本可以執行。
- 實際生成的檔案能正常開啟。
- 講義的章節和 Skill 功能完全一致。
- 模擬資料、範例及教學指令彼此對應。
- 不依賴使用者未提供的 API 金鑰。
- 若某項功能需要外部工具，明確列出前置條件及限制。
- 沒有偽造測試成功、外部連線或檔案建立結果。

最後請產生一份驗收報告，分別列出完成、部分完成、未完成的功能與理由。

## 九、發行方式

請提供：

1. 可在本專案中直接使用的原始 Skill。
2. 學員安裝教學。
3. 可供下載的工具包 ZIP。
4. 完整電子講義網站。
5. 10 組實際操作範例。
6. 最終驗收報告。

請勿未經同意就覆寫使用者全域 Codex Skill、部署網站或上傳遠端儲存庫。

## 十、開始執行

請先檢查目前工作區、Codex 版本及可用的 Skill 開發工具。

確認專案結構後，立即開始建立實際檔案，不要停留在規劃階段。

請依序完成每個階段，過程中測試並修復問題。

如果因工作量、環境權限或外部服務限制無法全部完成，請優先交付已實際驗收的完整功能，清楚記錄剩餘工作，不要宣稱所有功能已完成。

最終請告訴我：

- 哪 10 個 Skill 已完成。
- 哪些已通過實際測試。
- 講義首頁的本機路徑。
- Skill 安裝與使用方式。
- 學員工具包 ZIP 的位置。
- 尚有哪些需要人工確認的項目。

現在開始實際開發。
