## 四、新 Skill：法務文件審查助理

英文名稱：`legal-reviewer`

### 4.1 定位

這個 Skill 的目標是協助一般企業員工、採購人員、行政人員及法務人員，針對合約或具有法律性質的公司文件進行初步審閱。

它不是律師替代品，而是一套具備條款分析、風險辨識、修訂建議與法律依據查核能力的文件審查工作流程。

### 4.2 支援資料

至少支援：

- Word（DOCX）
- PDF（可擷取文字的 PDF）
- TXT、Markdown
- 使用者直接貼上的合約內容

掃描型 PDF 若無可用 OCR 工具，請明確告知限制，不能假裝已完整讀取。

### 4.3 主要功能

**A. 合約條款分析**

自動辨識並整理：

- 合約當事人與合約目的
- 合約期限及自動續約條件
- 付款條件與付款期限
- 違約責任、賠償責任及責任上限
- 保密及個人資料保護條款
- 智慧財產權歸屬
- 終止合約條件
- 爭議解決及適用法律
- 其他可能影響企業權益的特殊條款

不得只做文件摘要，必須逐項分析相關條款。

**B. 風險分級**

建立高、中、低三級風險標記。

對於每項風險，必須提供：

1. 原始條款文字或準確的位置。
2. 問題說明。
3. 可能造成的商業或法律影響。
4. 風險等級及判斷理由。
5. 可採取的處理方式。
6. 是否需要專業法務確認。

風險分級屬於輔助判斷，不得直接將風險評級等同於違法認定。

**C. 條款修改建議**

對有問題的條款，輸出：

- 原始條款
- 風險說明
- 建議修訂文字
- 修訂理由
- 待確認事項

修訂文字必須盡量明確、可實際參考，避免只寫「建議與律師討論」而沒有提供任何具體分析。

**D. 公司文件審查**

除了商業合約，也應能處理：

- 保密協議 NDA
- 合作協議
- 採購合約
- 服務契約
- 聘僱相關文件
- 公司內部規章
- 其他涉及法律條款的公司文件

依文件性質調整檢查項目，不得假設所有文件都是商業買賣合約。

**E. 法律問題分析**

使用者也可以直接詢問某個合約條款的法律風險。

必須先確認適用法域及必要背景。

若使用者提供台灣合約，可依台灣相關法律分析；但不能在適用法律未知時，直接假設一定適用台灣法律。

可取得可靠法律資料時，優先使用政府法規資料庫、官方主管機關或其他可核實來源，記錄法規名稱、條文、網址及查核日期。

若無法取得或驗證最新法規，不得自行編造法條或宣稱已完成法律查證。

### 4.4 輸出成果

至少能產出：

1. `合約審查報告.docx`
2. `合約風險清單.xlsx`
3. `條款修訂建議.md`

報告需要包含：

- 文件基本資訊
- 審查範圍
- 風險摘要
- 逐條審查內容
- 修訂建議
- 法律來源與適用限制
- 待人工確認事項

每項結論應可回查至原始文件。

### 4.5 啟動方式

學員只輸入：

`$legal-reviewer`

Skill 應直接詢問是否要提供合約或其他文件進行審查。

如果使用者已附上文件並說明目的，則直接開始，不要重問已知內容。

使用者也可以用自然語言啟動，例如：

「幫我看一下這份合約有沒有不合理的地方。」

不用要求學員貼固定格式 Prompt、建立 JSON 或手動執行 Python。

### 4.6 安全限制

- 不得憑空宣稱合約條款違法。
- 不得捏造法律、法條、判決或資料來源。
- 不得把 AI 分析結果冒充律師正式法律意見。
- 不得未經授權將機密文件上傳第三方服務。
- 重要法律結論須註明限制及待專業確認事項。
- 必須保留原始文件，不可直接覆寫原合約。

## 五、新 Skill：財務報表與對帳助理

英文名稱：`finance-assistant`

### 5.1 定位

這個 Skill 需要協助企業財務或會計人員，完成原始財務資料的整理、報表編製、銀行對帳與差異分析。

核心價值是：

**真正讀取會計資料、執行計算、核對金額，並交付可檢查的 Excel 財務工作成果。**

不能只是閱讀 Excel 後，以自然語言產生一份財務摘要。

### 5.2 支援資料

至少支援：

- Excel（XLSX）
- CSV
- 文字形式的帳務明細

可處理：

- 總帳
- 試算表
- 科目餘額表
- 銀行交易明細
- 公司收付款紀錄
- 預算與實際數據
- 各月份營運資料

### 5.3 主要功能

**A. 財務報表編製**

依照使用者提供的帳務資料，協助產生：

- 損益表
- 資產負債表
- 財務摘要
- 有足夠交易及分類資料時的現金流量報表

必須檢查：

- 會計期間
- 科目分類
- 借貸方向
- 金額合計
- 借貸平衡
- 資產負債表平衡關係
- 原始資料完整性

若資料不足以編製完整正式報表，應產出可合理完成的部分，並標記缺漏與限制。

不可為了平衡報表自行新增虛構交易或調整金額。

**B. 自動對帳**

提供兩份資料後，可進行：

- 銀行明細與公司帳務核對
- 應收應付明細比對
- 交易金額及日期檢查
- 重複交易偵測
- 未匹配交易整理
- 金額不一致項目辨識

輸出至少應區分：

1. 已確認匹配
2. 疑似匹配，待人工確認
3. 金額不符
4. 內部帳務缺漏
5. 銀行或另一來源缺漏
6. 疑似重複紀錄

不能因為兩個金額相同，就直接判定為同一筆交易。

對帳需綜合日期、金額、交易識別資訊與其他可用欄位，並防止同一交易被重複匹配。

**C. 財務差異分析**

支援：

- 本月與上月
- 本年與去年
- 預算與實際
- 部門與部門

自動計算：

- 預算金額
- 實際金額
- 差額
- 差異百分比
- 增減方向
- 異常項目

計算公式必須正確。

差異百分比通常以比較基準作為分母。若分母為零，必須標示無法直接計算百分比，不得任意填入數字。

金額變動的原因，若沒有資料支持，應列為可能原因或待查項目，不可自行當成事實。

### 5.4 輸出成果

依不同任務產出對應檔案，例如：

- `財務報表.xlsx`
- `銀行對帳結果.xlsx`
- `財務差異分析.xlsx`
- `財務分析報告.docx`

Excel 至少包含：

- 分析結果
- 原始資料或來源對照
- 計算依據
- 待人工確認項目

必要時包含圖表，並使用清楚的台灣繁體中文欄位名稱。

### 5.5 運算要求

這個 Skill 必須實際使用 Python 及適合的 Excel 函式庫完成處理。

所有關鍵金額應由可重現的程式邏輯計算。

不能讓語言模型直接憑感覺填入結果。

必須注意：

- 負數與沖銷交易
- 相同金額的重複交易
- 交易日期不同
- 空白欄位
- 不同幣別
- 重複列
- 預算為零
- 缺少會計科目
- 金額精度與四捨五入
- 不同會計期間
- 原始資料是否足以完成財務報表

若需指定會計準則、幣別或會計期間，但資料本身沒有提供，應視重要性詢問使用者。

不可以任意把不同幣別混在同一個合計。

不得自動修改、過帳或覆寫使用者原始帳本。

### 5.6 與既有 Excel Skill 的區別

請保留 `data-analyst`。

兩個 Skill 的定位必須區分：

- `data-analyst`：一般 Excel 資料整理、描述統計、數據分析、視覺化。
- `finance-assistant`：會計報表編製、財務資料核對、對帳、預算差異分析。

如果兩者需要相同的 Excel 讀寫功能，可以共用程式碼，但使用者操作介面及專業工作流程應保持獨立。

### 5.7 啟動方式

學員只需要輸入：

`$finance-assistant`

Skill 應簡單詢問使用者目前要進行財務報表編製、對帳還是差異分析。

如果使用者已有明確需求與附件，直接處理，不需要再次詢問功能選項。

也應支援自然語言，例如：

「幫我把這個月的公司帳跟銀行明細對一下。」

### 5.8 安全限制

- 不得虛構會計交易或缺漏金額。
- 不得自行調整帳務來讓報表平衡。
- 不得擅自修改原始財務資料。
- 不得未經授權上傳或傳送公司財務資料。
- 計算過程與來源必須可回查。
- 未完成核對的結果不得宣稱已通過正式會計查核。

## 六、所有 Skill 的共同操作規則

本項為這次修改的重要要求。

九個 Skill 都必須維持「直接啟動、必要時才詢問」的使用方式。

### 6.1 不要求固定格式提示詞

使用者可以：

- 直接輸入 `$skill-name`
- 提供附件並提出需求
- 使用自然語言說明工作

Codex 應依據 `SKILL.md` 自行判斷工作流程。

不能要求學員：

- 手動讀取 SKILL.md
- 填寫 JSON
- 自行找 Python 腳本
- 貼上很長的格式化 Prompt
- 自行確認技能內部路徑

### 6.2 缺少資訊才詢問

若資料已經足夠，直接處理。

若缺少必要文件或關鍵資訊，只詢問完成任務真正必要的部分。

不重要或可選的欄位應保留待確認，不應阻擋整個工作流程。

### 6.3 必須交付實際成果

任務有要求產檔時，必須實際生成 DOCX、XLSX、PPTX 或對應格式。

不能只回覆「已經幫你產生報告」，卻沒有真正建立檔案。

### 6.4 獨立安裝與執行

每個 Skill 必須能夠單獨放入其他 Codex 工作區使用。

檢查各技能的：

- SKILL.md
- scripts
- references
- agents
- requirements.txt
- 必要的共享執行資源

沿用目前 `tools/office_common.py` 及 `tools/sync_runtime.py` 的設計。

確保新 Skill 不會因缺少課程專案根目錄而無法執行。

### 6.5 模擬資料與實際資料分離

只有使用者明確要求練習、示範或測試時，才自動選用模擬資料。

真實工作任務不得默默載入教學範例。
