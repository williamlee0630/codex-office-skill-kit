# 客服案件交接 SOP｜教學模擬草案 正式版

## 文件狀態

文件版本：v0.1（本次教學草案標識）；核准狀態：待主管核准；非已生效公司制度。

## 文件目的與讀者

目的：減少交班資訊遺漏、重複回覆與客戶承諾遺漏。讀者：第一線客服與客服主管。

## 目的

建立可追查的客服交接，減少輪班後不明進度、重複回覆與承諾遺漏。

## 適用範圍

供第一線客服與客服主管處理交班前尚未結案的案件。客服系統與正式上線日待確認。

## 角色與責任

| 角色 | 工作 |
| --- | --- |
| 原承辦客服 | 整理未結案件資訊 |
| 接手客服 | 檢查缺漏、確認已讀與接手 |
| 客服主管 | 協調無人承接、權限不足與跨部門案件 |

## 交接流程

1. 原承辦人在交班前整理尚未結案的案件，記錄案件編號、問題摘要、目前狀態、已採取的處理、客戶已確認的承諾、下一步，以及有來源的期限。案件編號沿用原系統，不另外虛構。
2. 將交接記錄放在公司核准的共用位置，通知接手客服；具體工具與資料夾位置尚待確認。
3. 接手客服檢查資訊是否完整，回覆已接手；有缺漏時列出待補項目，不把未確認事項寫成完成。
4. 急件或可能超過已承諾期限的案件，交由客服主管協調；主管決定後補記處理方式。
5. 案件完成後，由實際處理者補記結果與結案依據，保留交接記錄以供追查。

## 例外處理

無人承接、權限不足或須跨部門處理：交客服主管協調。急件或可能超過已承諾期限：交主管協調，決定後補記處理方式。資訊缺漏：列待補項目，不標完成。

## 注意事項

只記必要客戶資訊，避免把個資貼到公開群組；不得自行新增折扣、退款或賠償承諾；回覆時限、保存年限、簽核層級及實際使用工具均未決，應標示待確認，不得補成既有制度。
