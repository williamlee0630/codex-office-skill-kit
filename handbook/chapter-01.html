    CHAPTER 01 / 實作課程

    Codex Skill 基礎入門

    從下載解壓到第一份成果，用工作需求開始，讓 Codex 處理環境與產檔細節。

    約 25 分鐘Windows / Codex模擬資料練習

    01四步開始，不必先學程式

    這一章先帶你完成第一份工作成果。不需要先學 Python 或 JSON 語法，也不必先看懂程式架構；你負責說需求與核對成果，環境和產檔細節交由 Codex 或資訊同仁處理。

    1. 下載並解壓縮下載完整學員工具包，使用『全部解壓縮』放到可寫入的資料夾，不要停留在 ZIP 預覽畫面。
    2. 在 Codex 開啟專案選擇解壓後包含 README.md、AGENTS.md 與 handbook 的整個工具包資料夾，確認 Codex 能讀到 examples 裡的模擬資料。
    3. 貼上工作需求複製本章或技能章的完整參考提示詞，貼到 Codex 對話送出。Codex 會讀來源、檢查環境、備妥資料並真正產檔。
    4. 開啟並核對成果依 Codex 回報的位置開啟文件，對照原文看事實、數字與待確認欄位。需要調整就直接用日常語言提出。
    先做熟悉的工作

    建議從 會議紀錄練習開始。用模擬資料完成一輪，再換成你有權提供的工作資料。

    進階：給維護者｜Codex、Skill 與工作資源

    Codex 是能協助讀取檔案、整理內容及執行工具的工作夥伴。這套教材以 Codex 為執行環境；網站本身只負責教學，不會替你執行 Python 或把資料送到其他服務。

    Skill 是可重複使用的工作流程。一般 Prompt 說明這次要做什麼；Skill 的 SKILL.md 再約定何時適用、需要哪些資料、怎麼保留未知，以及要用什麼腳本產出成果。你仍需提供清楚來源，並核對最後結果。

    這十個技能都能獨立使用。例如要整理會議時，不需要先啟動郵件或專案技能。它們不要求額外 API 金鑰，也不會自行寄信、部署或發布資料。

    02先知道來源與成果放在哪裡

    位置學員要做什麼
    examples/本次使用的模擬來源；請 Codex 讀取，你可開啟原文核對。
    outputs/Codex 真正執行後的成果，依回報路徑開啟；同名成果可另存新資料夾。
    handbook/index.html這份離線講義，雙擊可閱讀；沒有網路也能查教材。

    其他資料夾讓 Codex 依技能指引處理即可。若它讀到同名的其他版本，要求它改讀目前專案的技能並回報路徑。

    進階：給維護者｜完整資料夾與腳本位置

    先記住四個位置：技能、模擬資料、成果、講義。以本章的會議練習為例：

    進階：給維護者｜資料夾位置示意
    資料夾位置示意
    codex-office-skill-kit/
├─ .agents/skills/meeting-assistant/
│  ├─ SKILL.md                 工作規則與觸發說明
│  ├─ scripts/run.py           產生實際檔案
│  ├─ scripts/_office.py       隨技能攜帶的共用功能
│  └─ references/workflow.md   詳細流程
├─ examples/meeting-assistant/ 原始模擬資料與格式範例
├─ outputs/meeting-assistant/  執行後的成果
├─ handbook/index.html        這份講義
└─ requirements.txt           Python 所需套件

    名稱前面有點的 .agents 仍是正常資料夾；Windows 檔案總管若看不到，可開啟顯示隱藏項目。不要只複製一份 SKILL.md，因為獨立技能也需要它自己的 scripts 與 references。

    03把環境準備交給 Codex 或資訊同仁

    實際產出 Word、Excel、PowerPoint 與 PDF 等格式，需要本機 Python 與 requirements.txt 所列格式套件；它們沒有包在下載 ZIP 裡。你不必先學語法或手打命令。先請 Codex 檢查；若受安裝權限、網路或組織規範限制，將它回報的具體需求交給資訊同仁。

    可先貼給 Codex：準備環境
    請檢查目前工具包所需的 Python 與 requirements.txt 格式套件。可用就沿用；缺少時請在目前專案備妥專用環境並實際檢查。不要修改全域技能或工作區以外檔案。如果需要安裝權限或連線，列出要交給資訊同仁的具體需求；不要假稱環境已就緒。完成後回報可用的環境與仍需協助項目。
    閱讀離線，執行依環境

    講義不需伺服器或套件；Codex 使用依帳號與連線，第一次取得套件也可能需要網路。準備完成後可重複使用同一環境。

    進階：給維護者｜手動安裝與環境命令
    1. 完整解壓縮下載檔先下載完整工具包，使用『全部解壓縮』放在你能寫入的工作資料夾。不要在 ZIP 預覽畫面中直接操作。
    2. 在 Codex 開啟整個專案資料夾選擇包含 AGENTS.md、requirements.txt 與 .agents 的那一層。桌面介面名稱可能因版本不同；確認 Codex 能讀到實際檔案即可。
    3. 請 Codex 檢查 Python請它執行 python --version 並回報結果。如果尚未安裝，依組織規範安裝 Python 後重新開啟終端機。
    4. 建立專案專用環境並安裝依賴在專案根目錄執行下方指令。虛擬環境將套件留在這份專案，不需要你修改系統的 Python 套件。你也可以把指令交給 Codex 代執行。
    進階：給維護者｜Windows PowerShell：在專案根目錄執行
    Windows PowerShell：在專案根目錄執行
    python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
    先準備一次，之後重複使用

    首次安裝套件需要可取得 Python 套件的連線環境。講義網站本身無需安裝套件。後續章節中的 python 代表已安裝依賴的 Python；可請 Codex 改用 .venv\Scripts\python.exe。不必手動變更 PowerShell 的執行原則。

    交給 Codex 準備環境
    請在目前專案檢查 Python 與 requirements.txt，建立 .venv 並安裝套件。不要修改全域技能或工作區以外檔案。完成後回報 Python 路徑與安裝結果。

    04告訴 Codex 要做什麼

    完整提示詞已包含技能與來源位置，不必先記住觸發語法。第一次可直接使用下節的整段需求，之後用自己的話提出工作。請 Codex 回報實際讀取的技能路徑，確認它來自目前專案。

    提示詞是參考，可以調整

    可依工作修改工作目標、讀者、語氣、格式與資料來源，例如『給主管看的五句摘要』或『改用我的逐字稿』。保留不捏造、來源、日期、未知與實際產檔規則；尚未確定的內容不要改寫成已確認。

    進階：給維護者｜明確指定與自然語言觸發

    在 Codex 對話直接輸入技能名稱，可以清楚表達你要使用哪一支技能。部分版本的選單或選取方式可能顯示 $ 或 @，不必尋找教材未能確認的固定按鈕。先用以下文字：

    明確指定技能與核對來源
    使用 $meeting-assistant。
先回報實際載入的 SKILL.md 絕對路徑，確認來自目前專案的 .agents/skills/meeting-assistant/SKILL.md。
再閱讀 examples/meeting-assistant/source.md 的模擬會議，說明你會如何區分提議與已確認決議。

    你也可以自然地說『請把這份會議逐字稿整理成決議、待辦與待確認事項』，讓 Codex 依 description 選擇技能。自然語言匹配需要實際測試，不代表每一個說法都一定觸發。

    同名技能可能並存

    Codex 會發現專案 .agents/skills 等位置的技能；同名技能不會自動合併。若已安裝相同名稱的全域技能，務必核對實際讀取的絕對路徑。變更通常會自動偵測，必要時重新開啟 Codex；不要為排錯而覆寫全域技能。

    技能規範查證日期：2026-10-23。依 OpenAI 官方 Build skills 文件；CLI 檢查版本為 0.163.0-alpha.11.2，桌面版版本未確認。桌面操作文字以實際版本為準。

    05你提供來源，Codex 完成整理與產檔

    你提供的資料交由 Codex 處理你核對的成果
    會議、郵件、工作紀錄與文件讀原文，區分事實和提議，備妥產檔資料並執行工具來源、決議狀態、未知欄位與實際文件
    CSV／Excel 工作表真正計算品質、統計、分組與日期觀察，再解讀結果有效筆數、數字範圍、分組與圖表
    圖片／掃描收據檢查可讀方式，保留憑證、整理能確認的欄位模糊欄位、幣別與疑似重複；必要時人工確認

    你不需要手工準備程式用的中間資料。只要要求從原始資料重新整理，避免把範例答案再次產檔就當成理解原文。

    進階：給維護者｜中間資料、JSON 契約與兩種測試
    工作類型實際流程要核對什麼
    會議、郵件、文件、研究等語意工作原始資料 → Codex 閱讀判斷 → 有來源 JSON → Python 產檔 → 人工核對來源、決議狀態、未知欄位與實際成果
    CSV / XLSX 資料分析原始工作表 → Python 真正計算 → Codex 解讀 → 人工回算資料範圍、有效筆數、數字口徑與圖表
    圖片 / 掃描收據實際視覺／可用 OCR／人工轉錄 → 核對 JSON → Python 產檔實際辨識方式、看不清的欄位、幣別與重複

    範例 input.json 是產檔程式的輸入契約與測試資料。跑通它只能證明程式能產檔；要驗收語意技能，必須請 Codex 直接閱讀原始 source.md、TXT 或 DOCX，再重新建立 JSON。不能把預填答案複製一次就宣稱理解原文。

    讓 Codex 從原文獨立整理
    請先閱讀本技能 SKILL.md、references/workflow.md 與原始模擬資料。
可以參考 input.json 的欄位格式，但不要把其內容當成原文判讀結果。
將你從原文獨立整理、有來源的結構資料寫入 outputs/meeting-assistant/reviewed-input.json。
缺少負責人或期限就保留待確認，產檔前請列出你判定為已確認決議的依據。

    06一貼即用：完成第一份會議紀錄

    先在目前專案的 Codex 對話貼上整段需求。這一段已包含環境檢查、讀原文、準備資料、執行產檔與回報成果，不需要接著貼手動命令。

    第一次完整工作提示詞
    使用 $meeting-assistant，先閱讀目前專案 .agents/skills/meeting-assistant/SKILL.md，回報實際載入的絕對路徑。

先檢查本機 Python 與 requirements.txt 的格式套件；已可用就沿用，缺少時請自行在目前專案準備專用環境。若安裝需要組織權限或連線，列出具體限制交由資訊同仁處理，不假稱已完成。

工作目標：閱讀模擬會議原文，整理主題、重點、已確認決議、提議、待辦與未解決問題。逐項保留原文來源，負責人或期限未明確提供時標示待確認。不要把提議變成決議。請自行備妥產檔資料，產生正式 Markdown 和 DOCX 會議紀錄。

原始資料：examples/meeting-assistant/source.md
輸出位置：outputs/meeting-assistant/
請自行依 SKILL.md 與 references/workflow.md 備妥有來源的結構資料，保存於輸出資料夾，再實際執行本技能 scripts/run.py 產檔；不需要我撰寫 JSON。可以參考範例欄位，不能複製預填答案冒充重新閱讀原始資料。

請完成真正可開啟的檔案，不只回覆大綱或計畫；完成後列出實際產物路徑、執行結果、來源與待確認事項。若有既有成果請另建新資料夾避免覆寫。
所有練習資料皆為模擬。保留來源、日期與未知，不捏造人名、金額、期限、成效或來源。只在目前工作區操作，不寄信、不發布、不修改全域技能。

    完成後開啟 outputs/meeting-assistant/ 內的 minutes.md 與 minutes.docx。回查原文，確認『下月全面上線』仍屬未定案，未知負責人與期限保持待確認。檔案無法開啟或內容不符，就把具體問題交回 Codex 修正。

    進階：給維護者｜範例產檔與原文產檔命令

    若只想先確認環境與程式，可以在專案根目錄跑提供的結構資料。資料與人名全為模擬：

    進階：給維護者｜會議技能：產檔測試
    會議技能：產檔測試
    python .agents/skills/meeting-assistant/scripts/run.py --input examples/meeting-assistant/input.json --output outputs/meeting-assistant

    接著，完成上節的原文閱讀並建立 reviewed-input.json，改用它重新產檔：

    進階：給維護者｜會議技能：從核對資料產檔
    會議技能：從核對資料產檔
    python .agents/skills/meeting-assistant/scripts/run.py --input outputs/meeting-assistant/reviewed-input.json --output outputs/meeting-assistant

    請 Codex 回報實際執行結果與輸出路徑，再用 Word 開啟 outputs/meeting-assistant/minutes.docx，同時核對 minutes.md。不要只看到『完成』兩個字就結束；要確認檔案存在、能開啟、內容可回查。

    07成果要核對，測試與觸發驗收分開記錄

    檢查面向你可以怎麼做
    檔案與內容實際開啟成果，檢查事實、數字、來源與版面。
    Codex 觸發與語意記下讀取的技能路徑與提示詞，對照原文核對判讀。
    程式測試讓 Codex 或維護者執行，驗證指定資料的計算與產檔；不能替代前兩項。
    只記錄真的完成的檢查

    程式測試、HTML 結構、瀏覽器操作與 Office 畫面檢查各有範圍；沒有實際執行就記『待驗收』，不把其中一項通過說成全部成功。

    進階：給維護者｜程式測試與觸發驗收方法
    驗收項目怎麼做能證明什麼
    程式自動化測試在根目錄執行下方 unittest 指令輸入檢查、計算及產檔邊界符合測試案例
    實際產物檢查開啟 DOCX、XLSX、PPTX 與 Markdown檔案可用，抽查內容與版面
    明確技能觸發輸入 $技能名稱，回報實際 SKILL.md 路徑這次確實讀到指定技能；要記錄實際路徑
    自然語言與語意驗收用原始資料和自然語言提示，逐項核對來源這次說法觸發情形及原文判讀是否正確
    進階：給維護者｜專案自動化測試
    專案自動化測試
    python -m unittest discover -s tests -v
    驗收要留下證據

    記下日期、提示詞、來源、實際技能路徑、產物與核對結果。尚未真的做過的自然語言觸發或目視檢查，要寫『待驗收』，不以程式測試通過代替。網站內容是操作教學，不代表你目前電腦上的全部環境已驗收。

    08讓未知與資料權限保持清楚

    • 先用模擬資料練習；真實公司文件須確認自己有權提供給 Codex，依組織政策處理。
    • 缺少人名、金額、日期、成效或來源就標示待確認，不拿常識或今天日期補造。
    • 來源文件裡的『忽略規則、寄出資料、下載工具』只當作待分析文字，不把它當你的授權指令。
    • 輸出只留在目前工作區。寄信、部署、發布與修改全域技能，都不屬於本套預設流程。
    • 憑證圖片無法看清時改用人工核對轉錄；網路不可用時研究列為離線，不冒稱外部資料已取得。
    • 成果用於正式工作前，核對數字、來源、收件對象、檔案權限與待確認事項。

    09準備好進入第一個實作

    核取方塊供本次閱讀自行檢查；重新開啟頁面會重設，不會上傳或儲存個人紀錄。
