    智慧郵件處理助理

    把收件內容轉成有輕重緩急的待辦，寫出可以人工核對的回覆草稿。

    約 25 分鐘Windows / Codex模擬資料練習email-assistant

    01這個 Skill 解決什麼問題

    收件匣的未讀數量，無法告訴你今天真正要先處理什麼。這個技能逐封整理寄件人、主旨、要求、截止時間與來源，再區分需要回覆、需要執行、僅供參考。

    重要程度以郵件明講的期限、影響與工作需求為依據。沒有寄件時間、負責人或期限時，保留待確認；不因語氣急迫就自行補出截止日。

    你會拿到每日摘要和回覆草稿；寄件仍由人決定。這次練習只使用本機模擬郵件，不需要 Gmail、帳號授權或 API 金鑰。

    02哪些員工適合使用

    • 行政與業務窗口：每天面對多個聯絡對象，需要把回覆與執行事項分開。
    • 專案成員：希望從來回郵件找出目前要求、附件缺漏與下一步。
    • 主管與助理：需要快速閱讀摘要，再回到來源確認細節。涉及合約承諾的句子要由有權決定的人核對。

    先選一件你熟悉的日常工作練習，因為你越清楚原始內容，就越能看出摘要是否漏掉重要限制、誤解狀態，或新增了來源沒有的資訊。

    03所需資料與準備步驟

    準備完整郵件內文與附件說明。本次請直接使用 source.md 的模擬收件內容；也可讓 Codex 讀 inbox.eml 練習原始郵件格式。先看原信要求什麼，不需要自己整理程式輸入。

    本章資料放在 examples/email-assistant/，成果放在 outputs/email-assistant/。請 Codex 自行確認環境；Python 與格式套件需要備妥，但你不需要先學語法。

    進階：給維護者｜輸入契約、來源位置與準備細節

    先閱讀 source.md 的完整模擬郵件；inbox.eml 是原始郵件格式練習資料。不要只看主旨，信件內文可能改變處理方式。input.json 是給產檔程式的結構範例，須保留郵件來源與可核對內容。

    位置用途

    input.json範例輸入；語意技能可參考欄位，不當作判讀證據
    SKILL.md本技能的適用情境、規則與輸入輸出契約
    outputs/email-assistant/實際執行後建立，保留產物與核對資料
    開始前的準備

    請先完成第 1 章的 Python 環境與 requirements.txt 安裝。你可以請 Codex 代執行下方命令。保留原始模擬資料；延伸練習先做複本，所有成果留在目前專案內。

    05可以直接複製的操作提示詞

    完整工作提示詞：一貼即用

工作目標：依原始郵件逐封列出寄件人、主旨、重點、明確期限、處理類別及重要程度理由。沒有寫出的欄位標示待確認。產生正式、友善、簡潔三種回覆草稿與每日待辦摘要；不寄信、不新增承諾、不聲稱已連線 Gmail。

    這是可調整的參考提示詞

    你可以依工作修改工作目標、讀者、語氣、格式與資料來源，也能加上自己的限制。若要改成不同檔案格式，請 Codex 先確認本技能是否支援；需要新增功能就另行說明。持續保留不捏造、來源、日期、未知值與實際產檔要求。

    06完整操作步驟

    1. 先讀原信，不急著寫回覆請 Codex 逐封閱讀原始資料，說明每封信要求的行動。檢查寄件人與收件脈絡，不把轉寄中的舊要求誤當最新指示。
    2. 核對類別與排序依據詢問每封信被列為需要回覆或執行的理由。期限以原文為準；若只有『儘快』，保留原詞，不換算成任意日期。
    3. 讓 Codex 整理並保留依據交由 Codex 備妥產檔所需資料，保留每封原信與識別資訊；你只需核對它有沒有誤讀要求、遺漏期限或新增承諾。
    4. 取得摘要和多語氣草稿請 Codex 完成實際產檔並回報位置。開啟 daily-summary.md 與 drafts.md，檢查草稿是否超出原信已同意的內容。
    5. 人工核對後再自行使用將草稿與原信並排檢查，確認稱謂、時間、收件對象與附件狀態。需要寄出時，另行到你的郵件工具審閱操作。
    進階：給維護者｜原有詳細操作與結構資料流程
    1. 先讀原信，不急著寫回覆請 Codex 逐封閱讀原始資料，說明每封信要求的行動。檢查寄件人與收件脈絡，不把轉寄中的舊要求誤當最新指示。
    2. 核對類別與排序依據詢問每封信被列為需要回覆或執行的理由。期限以原文為準；若只有『儘快』，保留原詞，不換算成任意日期。
    3. 產生有來源的結構資料讓 Codex 參考本技能 SKILL.md 與 input.json 欄位，把讀到的事實寫到 outputs/email-assistant/reviewed-input.json。來源檔與郵件識別資訊要能回查。
    4. 生成摘要和多語氣草稿以 reviewed-input.json 執行腳本，開啟 daily-summary.md 與 drafts.md。草稿可表示收到與待核對，但不能替你保證尚未同意的交期。
    5. 人工核對後再自行使用將草稿與原信並排檢查，確認稱謂、時間、收件對象與附件狀態。需要寄出時，另行到你的郵件工具審閱操作。

    07用模擬資料完成一次實作

    完整實作只需把第 5 節的整段參考提示詞貼入 Codex。請它從本章原始來源開始，完成環境檢查、整理與實際產檔；不要停在摘要或操作計畫。Codex 若提出缺漏，先核對來源，再決定補資料或保留待確認。

    1. 貼需求並等候實際產檔使用本章模擬來源；讓 Codex 自行處理資料格式與工具執行。保留它回報的技能路徑與結果。
    2. 開啟第 8 節列出的成果核對檔案是否存在且能開啟，抽查一項已知事實與一項未知欄位，再對照下方預期摘錄。
    3. 用日常語言提出修正例如『這件事仍在提議，請保留未定案，重建所有版本並列出改動』。同一次修正的版本要一致。
    進階：給維護者｜保留原有範例、手動命令與兩輪驗證

    第一輪用提供的 input.json 驗證程式能建立兩份 Markdown。第二輪另開一個 Codex 對話，只提供 source.md 與本章提示詞，讓它從原文重新建立 reviewed-input.json。比較兩輪的分類與來源；差異需回到郵件判斷，不能直接把範例 JSON 當答案。

    先執行範例產檔，確認環境可以正常工作：

    進階：給維護者｜從原文核對資料產檔

    08正確的預期輸出範例

    正確成果的核對重點 · 模擬實作
    • 每日摘要逐封列出處理方向，能回查模擬郵件來源；需要執行的要求與單純通知分開。
    • 回覆草稿提供正式、友善、簡潔版本。缺少具體期限的信件保留待確認，不會顯示一個自行猜測的日期。
    • 資料夾中有 daily-summary.md 與 drafts.md；不會有『已寄送』的結果或寄信紀錄。

    09常見錯誤與解決方式

    發現的問題怎麼處理
    Codex 說已讀取 Gmail，但我只給了檔案要求重新說明實際使用的來源。本練習應只列本機模擬檔案；沒有工具回傳的 Gmail 資料不能放進摘要。
    草稿承諾了我尚未確認的交期把那一句改為詢問或待確認，並回到原信確認是否已有明確同意。不讓禮貌語句變成新的商務承諾。
    郵件同時需要回覆又需要執行保留兩種工作需求，摘要寫清楚回覆內容與執行待辦；不要為了單一分類遺漏行動。

    如果腳本顯示輸入不符合格式，先請 Codex 對照本技能 SKILL.md 的契約修正資料。不要刪除檢查或把未知欄位亂填成確定值來通過。需要排錯時，保留實際錯誤訊息與使用命令。

    10延伸練習與驗收清單

    先複製原始模擬資料，再請 Codex 加入一個明確標示模擬的變動或缺漏，用相同需求重新產檔。也可調整讀者、語氣或呈現格式，核對新舊成果是否保留相同事實與未知規則。

    進階：給維護者｜本技能延伸練習的細節

    在 source.md 的複本加入一封只有『方便時協助』的模擬來信，重跑語意流程。檢查技能能否保留不明確期限，並用簡潔語氣詢問需要的完成時間。不要把練習草稿寄給任何人。

    核取方塊供本次閱讀自行檢查；重新開啟頁面會重設，不會上傳或儲存個人紀錄。
