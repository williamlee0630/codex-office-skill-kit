    會議紀錄整理助理

    把一段討論整理成能追蹤的會議紀錄，清楚分開決議、提議與待確認。

    約 25 分鐘Windows / Codex模擬資料練習meeting-assistant

    01這個 Skill 解決什麼問題

    逐字稿記錄了每一句話，卻不一定讓人看得出最後決定。這個技能將同一主題的說明整理在一起，找出已確認結論、仍在討論的提議與需要追蹤的工作。

    『可以考慮』與『就依這個版本執行』代表不同狀態。當原文沒有明確定案，紀錄就維持提議或待確認；不靠語氣猜測主管已經批准。

    完成後會得到 Markdown 與 Word 會議紀錄。負責人、期限和來源逐項保留，讓未出席的同事也能知道哪些工作已有人承接。

    02哪些員工適合使用

    • 行政與會議記錄人：需要將逐字稿改成可閱讀的正式紀錄。
    • 專案窗口與小組長：要在會後發現沒有負責人或期限的工作。
    • 主管與參與者：需要快速確認決議是否符合當時的討論。這個技能整理文字，無法替與會者補做決策。

    先選一件你熟悉的日常工作練習，因為你越清楚原始內容，就越能看出摘要是否漏掉重要限制、誤解狀態，或新增了來源沒有的資訊。

    03所需資料與準備步驟

    本次只需 source.md 的模擬逐字稿。先留意會議日期、提議與明確同意的句子；貼上下一節完整提示詞後，交由 Codex 讀原文並產生紀錄。音檔須先取得可核對的轉錄。

    本章資料放在 examples/meeting-assistant/，成果放在 outputs/meeting-assistant/。請 Codex 自行確認環境；Python 與格式套件需要備妥，但你不需要先學語法。

    進階：給維護者｜輸入契約、來源位置與準備細節

    練習使用 source.md 的模擬會議逐字稿。確認會議主題、日期與每段來源位置，先圈出『提議』與『確認』的原句。技能也可處理 TXT 或 DOCX 原文；音檔須先取得可核對的轉錄，不能把沒有辨識過的音訊當成已讀文字。

    位置用途
    examples/meeting-assistant/source.md本章練習來源；請先讀完整內容
    input.json範例輸入；語意技能可參考欄位，不當作判讀證據
    SKILL.md本技能的適用情境、規則與輸入輸出契約
    outputs/meeting-assistant/實際執行後建立，保留產物與核對資料
    開始前的準備

    請先完成第 1 章的 Python 環境與 requirements.txt 安裝。你可以請 Codex 代執行下方命令。保留原始模擬資料；延伸練習先做複本，所有成果留在目前專案內。

工作目標：閱讀模擬會議原文，整理主題、重點、已確認決議、提議、待辦與未解決問題。逐項保留原文來源，負責人或期限未明確提供時標示待確認。不要把提議變成決議。請自行備妥產檔資料，產生正式 Markdown 和 DOCX 會議紀錄。

    這是可調整的參考提示詞

    你可以依工作修改工作目標、讀者、語氣、格式與資料來源，也能加上自己的限制。若要改成不同檔案格式，請 Codex 先確認本技能是否支援；需要新增功能就另行說明。持續保留不捏造、來源、日期、未知值與實際產檔要求。

    06完整操作步驟

    1. 閱讀整份會議來源先看完 source.md，再請 Codex 用幾句話說明會議目的。確認日期來自文件，不用電腦今天的日期代替。
    2. 先標記狀態，再寫摘要逐項問『這是提議、討論中、已確認，還是待確認？』請它附原句或來源位置。沒有明確定案證據的內容，不能放入已確認決議。
    3. 核對每個待辦欄位負責人、期限、動作、來源要分開檢查。若有人說『再找人處理』，負責人仍為待確認；不要自行指定發言者。
    4. 交由 Codex 完成產檔讓 Codex 自行整理產檔所需資料、執行工具並回報真正建立的 minutes.md 與 minutes.docx；你不需要填寫資料格式。
    5. 開啟兩個版本確認Markdown 用來快速核對，DOCX 用 Word 或相容軟體開啟。確認決議、待辦與待確認事項都有列出，並比較同一項目的兩種版本是否一致。
    進階：給維護者｜原有詳細操作與結構資料流程
    1. 閱讀整份會議來源先看完 source.md，再請 Codex 用幾句話說明會議目的。確認日期來自文件，不用電腦今天的日期代替。
    2. 先標記狀態，再寫摘要逐項問『這是提議、討論中、已確認，還是待確認？』請它附原句或來源位置。沒有明確定案證據的內容，不能放入已確認決議。
    3. 核對每個待辦欄位負責人、期限、動作、來源要分開檢查。若有人說『再找人處理』，負責人仍為待確認；不要自行指定發言者。
    4. 建立 JSON 並執行產檔參照 input.json 的欄位把原文判讀寫到 reviewed-input.json，執行本技能 run.py。請 Codex 報告實際產出的檔案路徑。
    5. 開啟兩個版本確認Markdown 用來快速核對，DOCX 用 Word 或相容軟體開啟。確認決議、待辦與待確認事項都有列出，並比較同一項目的兩種版本是否一致。

    07用模擬資料完成一次實作

    完整實作只需把第 5 節的整段參考提示詞貼入 Codex。請它從本章原始來源開始，完成環境檢查、整理與實際產檔；不要停在摘要或操作計畫。Codex 若提出缺漏，先核對來源，再決定補資料或保留待確認。

    1. 貼需求並等候實際產檔使用本章模擬來源；讓 Codex 自行處理資料格式與工具執行。保留它回報的技能路徑與結果。
    2. 開啟第 8 節列出的成果核對檔案是否存在且能開啟，抽查一項已知事實與一項未知欄位，再對照下方預期摘錄。
    3. 用日常語言提出修正例如『這件事仍在提議，請保留未定案，重建所有版本並列出改動』。同一次修正的版本要一致。
    進階：給維護者｜保留原有範例、手動命令與兩輪驗證

    先用範例 JSON 跑通產檔，再從 source.md 獨立操作一次。刻意找到原文中尚未定案的提議，檢查它仍留在提議或未解決事項，而不是決議。將 reviewed-input.json 與 minutes.md 的來源一起交給同伴核對。

    09常見錯誤與解決方式

    發現的問題怎麼處理
    提議被放進已確認決議回到原文找正式同意的句子；找不到就降低狀態為提議或待確認，重新產檔。
    Word 檔無法建立確認已依第 1 章安裝 requirements.txt，請 Codex 把 Python 的錯誤完整顯示；不要把更改副檔名的文字檔當成 Word。
    只有摘要，沒有待辦負責人檢查輸入 JSON 是否漏了待辦陣列與來源。原文未提到就列待確認；原文有資料卻遺漏，則修正判讀。

    如果腳本顯示輸入不符合格式，先請 Codex 對照本技能 SKILL.md 的契約修正資料。不要刪除檢查或把未知欄位亂填成確定值來通過。需要排錯時，保留實際錯誤訊息與使用命令。

    10延伸練習與驗收清單

    先複製原始模擬資料，再請 Codex 加入一個明確標示模擬的變動或缺漏，用相同需求重新產檔。也可調整讀者、語氣或呈現格式，核對新舊成果是否保留相同事實與未知規則。

    進階：給維護者｜本技能延伸練習的細節

    在來源複本增加一句『預算再議，今天不定案』，重新整理。比較兩版紀錄，確認狀態變動可解釋、沒有沿用舊版的已確認結論。再把同一紀錄改寫成五句主管摘要，但保留完整正式版。

    核取方塊供本次閱讀自行檢查；重新開啟頁面會重設，不會上傳或儲存個人紀錄。
