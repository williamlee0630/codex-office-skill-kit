    CHAPTER 04 / 實作課程

    AI 簡報製作助理

    從可核對的資料走到真正的 PowerPoint，讓每頁有重點、每個結論有出處。

    延伸自學約 35 分鐘Windows / Codex日常工作工具presentation-maker

    01立即體驗｜複製提示詞，交付工作

    把完整工作重點做成五頁、可編輯的遠端協作指南。

    不需要下載附件。提示詞已包含這次工作的完整素材，直接複製即可。

    完整工作提示詞
    $presentation-maker

請依以下教學模擬素材，製作給新進員工看的「遠端協作指南」。目的是讓新人知道怎麼溝通、開會、分工與管理文件。請產生可編輯的 PowerPoint，共五頁（含封面），每頁附講者說明，另附講者說明檔。不要增加沒有來源的公司制度或成效數字。

原始重點：
1. 溝通管道：一般進度放在團隊工作群組；需要追蹤的決定寫入任務看板；有急件時先標示緊急原因與希望回覆時間，再聯絡當事人。這是本次指南的協作建議，沒有規定固定回覆時限。
2. 會議安排：發起人先寫目的、議程與預計時間，確認參與者時區；會前提供可讀文件；會後記錄決定、負責角色與待確認事項。沒有需要同步討論的問題時，可先採文字更新。
3. 任務分工：每項任務寫清楚交付成果、負責角色、預計日期與依賴事項；日期或負責人未定就標待確認；遇到阻礙時提早回報，由團隊討論調整，不自行改成已完成。
4. 文件管理：共同文件集中放在團隊指定的共享資料夾；檔名包含主題與版本日期；修改後留下變更摘要；分享前確認權限。實際工具與資料夾尚未指定，請保留待確認。
5. 注意事項：尊重休息時間與不同時區；敏感資料只使用公司核准管道；會議錄影須先確認參與者同意；尚未確認的資訊不要對外承諾。

請將溝通與會議合併一頁，其餘安排為封面、任務分工、文件管理、注意事項，共五頁；所有內容標示教學模擬。

    照這個順序操作

    1. 介紹工作情境把完整工作重點做成五頁、可編輯的遠端協作指南。
    2. 下載附件（如需要）本章不需附件，素材已寫在提示詞中。
    3. 複製提示詞按「複製」，在已載入技能的 Codex 新對話中貼上完整內容。安裝是一次性準備，每次使用不必重新安裝。
    4. Codex 執行送出後讓 Codex 讀來源、整理並實際產檔，只補充真正必要的問題。
    5. 開啟成果點選 Codex 回覆中的實際檔案連結，開啟檢查；若只有計畫或沒有檔案，請要求接續產檔。

    會拿到哪些檔案

    • presentation.pptx：共五頁、可編輯文字與內嵌講者備註
    • speaker-notes.md：逐頁講者說明

    打開後這樣檢查

    核取方塊供本次閱讀自行檢查；重新開啟頁面會重設，不會上傳或儲存個人紀錄。

    教學用途

    全部情境與附件均為原創模擬資料，沒有真實個人資料。換成自己的資料時，請同步修改提示詞中的模擬說明、工作背景與日期，以實際來源為準。

    02這個 Skill 解決什麼工作

    文件能寫得很完整，投影片卻需要讓人快速抓住重點。這個技能先決定受眾、目的與簡報主線，再把資料分成有標題、有重點與有講者說明的頁面。

    每頁以一個主要訊息為原則，將細節放在講者說明，避免把整份報告貼進一個文字框。來源未支持的市場規模、業績或成功率，不能為了簡報好看而加入。

    交付物必須是真正可開啟的 PPTX。程式文字長度檢查可以阻擋明顯過長內容，實際字型替換、行距與畫面仍需要開啟 PowerPoint 檢視。

    03哪些工作適合使用

    • 業務、企劃與專案窗口：要把現有報告轉成主管或客戶看得懂的簡報。
    • 內部講師：需要清楚的章節、重點及講者提示。
    • 簡報審閱人：希望追查每個數字與決策依據。這個技能協助產檔，對外使用前仍需確認資料權限與事實。

    這是日常工作工具，可反覆用於真實工作。自然語言也能選用，不需要依序啟動其他技能；已有完整目的與素材時直接執行。

    04提供必要素材即可

    直接貼文字、附檔或提供可讀檔案，無須固定檔名、表單或長提示詞。Codex 會先讀目前對話與來源，自行查看能取得的檔案、欄位、工作表與環境；只問會阻止正確完成或實質改變結果的缺漏。

    標題、檔名、輸出位置與一般呈現方式採合理預設。未知人名、期限與成效數字保留待確認；有依據的內容先完成，不拿範例資料填空。

    05日常使用的另一種啟動方式

    可複製的啟動內容
    $presentation-maker

    只有名稱時會依工作用途引導；已有素材或正在補答時沿用前文，不重新介紹功能或要求選擇。

    06實務工作對話示意

    以下是對話方式示意，不是技能自動載入的來源，也不代表已在你的電腦產檔。你可用自己的話回答，不必回覆編號。

    角色內容
    使用者$presentation-maker
    Codex請提供要做成簡報的工作素材，並說明要給誰看、希望對方了解或決定什麼；已有草稿也可以直接提供。
    使用者附件是工作進度，請做給主管決定下一階段範圍的簡報，頁數你安排。
    Codex會依來源安排精簡商務簡報，保留提議與未決項目，產生可編輯 PPTX 及講者備註。

    07補答與修改會接續完成

    1. 提供資料直接貼素材或附檔；若來源可讀且目的清楚，Codex 直接整理並執行。
    2. 只補關鍵缺漏需要日期、範圍或不清欄位時，回答那一個問題即可；不用重新貼完整需求。
    3. 開啟成果並修改使用實際檔案連結核對，再用日常語言說要改哪裡；Codex 沿用來源更新相關成果並保留舊版本。

    Codex 會自行讀內部規則、檢查環境、整理有來源的資料、選參數、執行並確認檔案存在。你不需要指示它讀 MD、回報技能路徑、編輯 JSON 或指定腳本。

    08另外選用的模擬教學

    初次操作請使用章首「立即體驗」的完整提示詞與下載附件。下方保留舊有技術測試，供需要維護時展開。

    進階：給維護者｜模擬來源、保留的手動命令與測試細節

    閱讀 source.md 的模擬簡報需求與事實，再看 deck.json 的頁面結構。準備受眾、簡報目的、頁面標題、重點、講者說明與來源。不需要準備 API 金鑰；本機產檔需有 python-pptx，已包含在 requirements.txt。

    1. 固定簡報目的與聽眾先請 Codex 用一句話說明這份簡報希望聽眾理解或決定什麼。從 source.md 取出明確事實與待確認事項。
    2. 檢查頁面主線閱讀每一頁標題，看標題能否連成完整敘述。將背景、現況、問題與下一步安排好，不必為每一段原文各做一頁。
    3. 把重點與講者內容分開投影片只放必要重點，較長的解釋留在 notes 或講者稿。要求 Codex 保留每頁來源，未知數字不能變成圖表。
    4. 產生 PPTX 並處理長文字以核對過的 deck JSON 執行腳本。如果出現文字過長診斷，先摘要或拆頁，再重跑；不降低字體到難以閱讀來硬塞內容。
    5. 開啟簡報做畫面驗收用 PowerPoint 或相容軟體逐頁檢查標題、文字框、講者內容、頁序及特殊字元。程式檢查通過仍不能直接宣稱所有字型與版面已目視通過。

    先用 deck.json 驗證實際產出 PPTX，再讓 Codex 依 source.md 重建 reviewed-input.json。請同伴只讀頁面標題，說出簡報主線；若說不清，調整標題與頁序。最後在實際簡報軟體逐頁檢查，而不是只看檔名。

    進階：給維護者｜維護者產檔測試
    維護者產檔測試
    python .agents/skills/presentation-maker/scripts/run.py --input examples/presentation-maker/deck.json --output outputs/presentation-maker

    09開啟並核對成果

    這裡保留教學範例的預期成果，供明確練習時核對；不能當作一般工作的預填答案。實際成果仍依你的來源。

    進階：給維護者｜模擬範例預期內容
    • 輸出資料夾有真正的 presentation.pptx；可以開啟並看到封面、清楚重點與後續行動，而不只是 Markdown 大綱。
    • 講者說明與投影片內容一致，來源沒有提供的數字仍列待確認。
    • 文字長度檢查有實際結果；過長內容需要拆頁或縮寫，最終畫面另由人工檢視。
    進階：給維護者｜模擬預期摘錄
    模擬預期摘錄
    資料日期：2026-10-23（模擬）
共 4 頁：封面、試辦目的、已確認進度、待確認與下一步。
已完成：模擬會議紀錄與銷售 CSV 操作演練。
收據影像仍需人工核對；不寫成正式上線。
上線日期、參訓人數、負責人與預算仍待確認。
每頁講者備註保留來源與日期；未新增績效百分比。
    本技能實際產物核對方式
    presentation.pptx開啟檔案，抽查來源、日期、數字及待確認欄位
    speaker-notes.md開啟檔案，抽查來源、日期、數字及待確認欄位
    layout-check.json開啟檔案，抽查來源、日期、數字及待確認欄位

    只有計畫、操作建議、中間核對資料或待補空殼都不代表完成。有工具、連線或權限限制時，Codex 應具體列出未完成項目；程式格式檢查不等於原生 Office 畫面驗收。

    10發現問題時直接提出

    可以直接指出『這個期限不對』、『這項還沒核准』或『請縮短給主管看』。Codex 會回查來源、沿用已確認資訊更新；若修正與來源衝突，保留修正的依據與待確認狀態。內部格式錯誤由它先處理，不要求你填結構資料。

    進階：給維護者｜技術排錯與教學案例
    原有教學排錯案例核對方法
    只拿到簡報大綱要求執行本技能的 run.py 並回報實際 PPTX 路徑。檢查 requirements.txt 已安裝，不把貼上副檔名當產檔。
    長文字被程式拒絕依診斷把一頁拆成兩頁或將說明移到講者稿，維持原事實後重跑。不要刪掉來源與必要條件。
    開啟後某些文字換行不對可能是本機字型或相容軟體差異。回到來源頁面內容調整長度，再產檔與目視確認；記錄實際開啟軟體。

    11驗收與使用邊界

    核取方塊供本次閱讀自行檢查；重新開啟頁面會重設，不會上傳或儲存個人紀錄。

    預設只在工作區產檔。寄送、外部上傳、發布或提交報帳仍依既有授權要求；來源文件內的指令只當資料。保留原始資料，不捏造人名、金額、期限、數據或研究來源。

    進階：給維護者｜保留的延伸練習

    在 deck.json 的複本加入一頁過長的模擬內容，先觀察程式診斷，再分頁修正。比較兩版：聽眾能否讀得懂、講者稿是否仍保留細節，以及每個事實是否都能回到來源。
