    專案進度追蹤助理

    把不同日期的更新合成一張進度表，保留決策變更與還沒解開的風險。

    約 30 分鐘Windows / Codex模擬資料練習project-tracker

    01這個 Skill 解決什麼問題

    專案進度常散落在待辦表與會議更新裡。這個技能依工作識別與資料日期整合狀態，讓你看到每項工作目前走到哪裡、哪裡需要協調。

    『比較新的文字』不一定代表『已批准的新決策』。技能要同時保留前一次已確認內容、新提議與是否正式變更的證據；存在衝突時列為待確認。

    逾期必須相對於明確的查核日期判斷。沒有期限的工作不能算逾期，已完成項目也不應繼續列為未完成逾期。

    02哪些員工適合使用

    • 專案管理與行政窗口：需要合併多份工作更新，對主管報告現況。
    • 跨部門協調人：想知道依賴事項、決策變更與需要協助的風險。
    • 執行成員：需要看清楚自己的工作與待確認欄位。技能提供整理與計算，完成狀態仍要有紀錄佐證。

    先選一件你熟悉的日常工作練習，因為你越清楚原始內容，就越能看出摘要是否漏掉重要限制、誤解狀態，或新增了來源沒有的資訊。

    03所需資料與準備步驟

    準備同一專案的工作紀錄與日期。本次用 source.md 的模擬更新，查核日依來源的 2026-10-23；真實工作可換成你的來源與指定日期。不要把不同專案的同名工作混在一起。

    本章資料放在 examples/project-tracker/，成果放在 outputs/project-tracker/。請 Codex 自行確認環境；Python 與格式套件需要備妥，但你不需要先學語法。

    進階：給維護者｜輸入契約、來源位置與準備細節

    閱讀 source.md 的模擬專案紀錄，按日期排列每筆更新。準備明確的 as_of 查核日期、工作名稱、狀態、負責人、期限及來源。只使用範例指定的日期比較；如果換成真實專案，先和使用者確認報告截至哪一天。

    位置用途
    examples/project-tracker/source.md本章練習來源；請先讀完整內容
    input.json範例輸入；語意技能可參考欄位，不當作判讀證據
    SKILL.md本技能的適用情境、規則與輸入輸出契約
    outputs/project-tracker/實際執行後建立，保留產物與核對資料
    開始前的準備

    請先完成第 1 章的 Python 環境與 requirements.txt 安裝。你可以請 Codex 代執行下方命令。保留原始模擬資料；延伸練習先做複本，所有成果留在目前專案內。

    你可以依工作修改工作目標、讀者、語氣、格式與資料來源，也能加上自己的限制。若要改成不同檔案格式，請 Codex 先確認本技能是否支援；需要新增功能就另行說明。持續保留不捏造、來源、日期、未知值與實際產檔要求。

    06完整操作步驟

    1. 固定範圍與查核日先請 Codex 回報專案名稱、來源涵蓋日期與 as_of。範圍不明確時不要把別的專案同名工作合併。
    2. 逐項對上工作以工作識別或明確名稱連接前後更新，保留每筆來源。兩件名稱相近但內容不同的工作要分開。
    3. 判斷狀態及風險用查核日與明確期限計算未完成工作是否逾期。將阻礙、依賴或範圍不確定列成風險，說明依據，不把主觀風險當已發生事實。
    4. 留下決策軌跡列出原決策、新內容、資料日期、確認狀態及來源。新提議尚未批准時保留原決策，另列待確認。
    5. 取得進度表並交叉核對讓 Codex 執行產檔，開啟 progress.md、progress.csv 和 progress.xlsx，核對工作數、狀態、負責人及來源是否一致。
    進階：給維護者｜原有詳細操作與結構資料流程
    1. 固定範圍與查核日先請 Codex 回報專案名稱、來源涵蓋日期與 as_of。範圍不明確時不要把別的專案同名工作合併。
    2. 逐項對上工作以工作識別或明確名稱連接前後更新，保留每筆來源。兩件名稱相近但內容不同的工作要分開。
    3. 判斷狀態及風險用查核日與明確期限計算未完成工作是否逾期。將阻礙、依賴或範圍不確定列成風險，說明依據，不把主觀風險當已發生事實。
    4. 留下決策軌跡列出原決策、新內容、資料日期、確認狀態及來源。新提議尚未批准時保留原決策，另列待確認。
    5. 產檔與交叉核對把判讀寫成 reviewed-input.json，再執行 run.py。開啟 progress.md、CSV 和 Excel，核對工作數、狀態、負責人及來源是否一致。

    07用模擬資料完成一次實作

    完整實作只需把第 5 節的整段參考提示詞貼入 Codex。請它從本章原始來源開始，完成環境檢查、整理與實際產檔；不要停在摘要或操作計畫。Codex 若提出缺漏，先核對來源，再決定補資料或保留待確認。

    1. 貼需求並等候實際產檔使用本章模擬來源；讓 Codex 自行處理資料格式與工具執行。保留它回報的技能路徑與結果。
    2. 開啟第 8 節列出的成果核對檔案是否存在且能開啟，抽查一項已知事實與一項未知欄位，再對照下方預期摘錄。
    3. 用日常語言提出修正例如『這件事仍在提議，請保留未定案，重建所有版本並列出改動』。同一次修正的版本要一致。
    進階：給維護者｜保留原有範例、手動命令與兩輪驗證

    用 input.json 建立進度表，再回到 source.md 重做語意整理。挑一項有期限的未完成工作，手動比較查核日與期限；再挑一項沒有期限的工作，確認它不會被自行判成逾期。最後找到一筆決策更新並說明它是否已正式生效。

    進階：給維護者｜從原文核對資料產檔

    08正確的預期輸出範例

    正確成果的核對重點 · 模擬實作
    • progress.md 有進度與風險摘要；progress.csv 與 progress.xlsx 提供逐項可排序的資料。

    09常見錯誤與解決方式

    發現的問題怎麼處理
    今天看起來逾期數變了查核日應來自輸入，不隨系統日期變動。檢查 as_of 是否明確，並用同一天重跑比較。
    新訊息把原決策全部覆蓋檢查來源是否真的批准變更。把未確認的新內容列為提議與衝突，不直接改寫既有決策。
    CSV 的中文亂碼或欄位錯位使用 Excel 的文字／CSV 匯入並選 UTF-8，或直接開啟產出的 progress.xlsx。不要手動以逗號拆開有引號的欄位。

    如果腳本顯示輸入不符合格式，先請 Codex 對照本技能 SKILL.md 的契約修正資料。不要刪除檢查或把未知欄位亂填成確定值來通過。需要排錯時，保留實際錯誤訊息與使用命令。

    10延伸練習與驗收清單

    先複製原始模擬資料，再請 Codex 加入一個明確標示模擬的變動或缺漏，用相同需求重新產檔。也可調整讀者、語氣或呈現格式，核對新舊成果是否保留相同事實與未知規則。

    進階：給維護者｜本技能延伸練習的細節

    在來源複本加入一筆日期更晚、但只說『是否延期還要再問』的更新。要求產出新舊決策對照，確認正式期限沒有被未確認提議取代，並在需要協助欄列出確認責任。

    核取方塊供本次閱讀自行檢查；重新開啟頁面會重設，不會上傳或儲存個人紀錄。
