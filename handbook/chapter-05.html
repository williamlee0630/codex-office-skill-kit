    CHAPTER 05 / 實作課程

    智慧週報生成器

    把零散工作紀錄寫成有成果、有問題、有下一步的週報，讓每個數字都有出處。

    約 25 分鐘Windows / Codex模擬資料練習weekly-report

    01這個 Skill 解決什麼問題

    一週做了很多事，週報卻常只剩工作清單。這個技能從紀錄找出工作情境、目標、採取的行動與結果，讓主管看得出進展與需要協助的地方。

    STAR 分別是情境、任務、行動、結果。它是整理角度，不是補資料的理由。沒有量測結果時寫已完成的交付內容或標示待確認，不憑空增加『效率提升百分之幾』。

    同一組事實會產生精簡與詳細兩版。精簡版用來快速閱讀，詳細版保留進度、來源、阻礙與下週安排；兩者不能出現互相矛盾的績效數字。

    02哪些員工適合使用

    • 行政、行銷、業務與營運成員：平日有工作紀錄，但需要整理成正式週報。
    • 專案窗口：要分清本週已完成、仍進行中與尚未開始的工作。
    • 團隊主管：需要迅速看見成果與要協助解決的問題。缺少量測資料的成果仍可描述，不必硬塞績效數字。

    先選一件你熟悉的日常工作練習，因為你越清楚原始內容，就越能看出摘要是否漏掉重要限制、誤解狀態，或新增了來源沒有的資訊。

    03所需資料與準備步驟

    準備指定一週的工作紀錄。本次用 source.md，期間為 2026-10-19 至 2026-10-23；來源中的下週安排需另外列出。你只需確認週期、讀者與要交付的兩種版本。

    本章資料放在 examples/weekly-report/，成果放在 outputs/weekly-report/。請 Codex 自行確認環境；Python 與格式套件需要備妥，但你不需要先學語法。

    進階：給維護者｜輸入契約、來源位置與準備細節

    先閱讀 source.md，確認模擬週報的開始日與結束日。把期間內的工作紀錄、可驗證成果、遇到的問題與下週計畫區分。跨週事項若只在期間外發生，要標示背景，不能算成本週新增成果。

    位置用途

    input.json範例輸入；語意技能可參考欄位，不當作判讀證據
    SKILL.md本技能的適用情境、規則與輸入輸出契約
    outputs/weekly-report/實際執行後建立，保留產物與核對資料
    開始前的準備

    請先完成第 1 章的 Python 環境與 requirements.txt 安裝。你可以請 Codex 代執行下方命令。保留原始模擬資料；延伸練習先做複本，所有成果留在目前專案內。

    這是可調整的參考提示詞

    你可以依工作修改工作目標、讀者、語氣、格式與資料來源，也能加上自己的限制。若要改成不同檔案格式，請 Codex 先確認本技能是否支援；需要新增功能就另行說明。持續保留不捏造、來源、日期、未知值與實際產檔要求。

    06完整操作步驟

    1. 確認週報期間請 Codex 先回報開始日、結束日與來源。來源不屬於這一週時，標示背景或移出本週成果。
    2. 逐項抽出成果與進度區分已交付內容與尚在進行的工作。可以寫『完成文件初稿』，不能把初稿寫成已獲核准或正式上線。
    3. 用 STAR 檢查說明是否完整為重要成果找出情境、任務、行動與結果。缺的欄位保留待確認或簡短說明，不用漂亮句子掩飾缺乏證據。
    4. 整理問題與下週計畫問題寫出影響與需要協助的內容。下週計畫要能執行，但只有原文確定的期限才填日期，避免產生新承諾。
    5. 取得兩版並對照讓 Codex 同時產生四份輸出，逐一開啟。核對兩版期間、人名、成果數字與工作狀態，不能只改其中一版而留下矛盾。
    進階：給維護者｜原有詳細操作與結構資料流程
    1. 確認週報期間請 Codex 先回報開始日、結束日與來源。來源不屬於這一週時，標示背景或移出本週成果。
    2. 逐項抽出成果與進度區分已交付內容與尚在進行的工作。可以寫『完成文件初稿』，不能把初稿寫成已獲核准或正式上線。
    3. 用 STAR 檢查說明是否完整為重要成果找出情境、任務、行動與結果。缺的欄位保留待確認或簡短說明，不用漂亮句子掩飾缺乏證據。
    4. 整理問題與下週計畫問題寫出影響與需要協助的內容。下週計畫要能執行，但只有原文確定的期限才填日期，避免產生新承諾。
    5. 生成兩版並對照把核對後內容寫入 reviewed-input.json，執行 run.py。打開四份輸出，確認兩版的時間、人名、成果數字與工作狀態完全相容。

    07用模擬資料完成一次實作

    完整實作只需把第 5 節的整段參考提示詞貼入 Codex。請它從本章原始來源開始，完成環境檢查、整理與實際產檔；不要停在摘要或操作計畫。Codex 若提出缺漏，先核對來源，再決定補資料或保留待確認。

    1. 貼需求並等候實際產檔使用本章模擬來源；讓 Codex 自行處理資料格式與工具執行。保留它回報的技能路徑與結果。
    2. 開啟第 8 節列出的成果核對檔案是否存在且能開啟，抽查一項已知事實與一項未知欄位，再對照下方預期摘錄。
    3. 用日常語言提出修正例如『這件事仍在提議，請保留未定案，重建所有版本並列出改動』。同一次修正的版本要一致。
    進階：給維護者｜保留原有範例、手動命令與兩輪驗證

    先產生範例的精簡與詳細週報，再讓 Codex 直接讀 source.md 重做。圈出三個最重要的結果，逐一指向原始紀錄。若某項只有行動、沒有量測成效，保持描述事實，不要自行換算百分比。

    09常見錯誤與解決方式

    發現的問題怎麼處理
    週報看起來很漂亮，但多了成長率要求它指出分子、分母與來源。無法回算就刪除該數字，改寫實際完成的工作。
    把期間外的工作算進本週先核對 period 與來源日期。可保留為背景，但要從本週成果移出，重新產生兩版。
    精簡版與詳細版不一致先修正共同的 reviewed-input.json，再同時重建輸出；不要只在其中一個 Word 檔手改而失去一致性。

    如果腳本顯示輸入不符合格式，先請 Codex 對照本技能 SKILL.md 的契約修正資料。不要刪除檢查或把未知欄位亂填成確定值來通過。需要排錯時，保留實際錯誤訊息與使用命令。

    10延伸練習與驗收清單

    先複製原始模擬資料，再請 Codex 加入一個明確標示模擬的變動或缺漏，用相同需求重新產檔。也可調整讀者、語氣或呈現格式，核對新舊成果是否保留相同事實與未知規則。

    進階：給維護者｜本技能延伸練習的細節

    在來源複本加入一項尚未量測成效的改善工作。要求用 STAR 呈現已做的行動與待確認的結果，再寫一個需要主管協助的具體問題。評估文字是否清楚，而不是看起來有多少漂亮數字。

    核取方塊供本次閱讀自行檢查；重新開啟頁面會重設，不會上傳或儲存個人紀錄。
