    CHAPTER 05 / 實作課程

    商務文件撰寫助理

    把原始事實寫成適合讀者的商務文件，正式與精簡兩版共用同一套證據。

    延伸自學約 25 分鐘Windows / Codex日常工作工具document-writer

    01這個 Skill 解決什麼工作

    一份商務文件需要讓讀者知道目的、背景、處理方式與下一步。這個技能依文件類型和對象整理架構，再調整用詞、段落及資訊順序。

    文字可以改得更清楚，事實不能跟著變大。原本是試辦，就不能改成已全面上線；原本沒有預算、期限或成效，就要保留待確認。

    這次練習會產生正式與精簡版本，並實際建立 Markdown 與 Word。你可以把正式版交給審閱人，再用精簡版快速溝通同一件事。

    02哪些工作適合使用

    • 行政、營運與企劃人員：要把零散筆記寫成提案、企劃或工作報告。
    • 業務窗口：需要正式清楚的商務信函與說明。
    • 文件覆核人：希望快速檢查日期、金額、要求與來源。涉及公司政策或對外承諾時，依內部程序審閱。

    這是日常工作工具，可反覆用於真實工作。自然語言也能選用，不需要依序啟動其他技能；已有完整目的與素材時直接執行。

    03提供必要素材即可

    直接貼文字、附檔或提供可讀檔案，無須固定檔名、表單或長提示詞。Codex 會先讀目前對話與來源，自行查看能取得的檔案、欄位、工作表與環境；只問會阻止正確完成或實質改變結果的缺漏。

    標題、檔名、輸出位置與一般呈現方式採合理預設。未知人名、期限與成效數字保留待確認；有依據的內容先完成，不拿範例資料填空。

    04只送出技能名稱

    可複製的啟動內容
    $document-writer

    只有名稱時會依工作用途引導；已有素材或正在補答時沿用前文，不重新介紹功能或要求選擇。

    05實務工作對話示意

    以下是對話方式示意，不是技能自動載入的來源，也不代表已在你的電腦產檔。你可用自己的話回答，不必回覆編號。

    角色內容
    使用者$document-writer
    Codex你想撰寫企劃、提案、信函或工作報告，還是修改現有文件？請提供素材或草稿，並說明希望達成的目的。
    使用者請把這份草稿改成給主管的提案，預算和負責人還沒決定。
    Codex會保留可證實事實，把預算和負責人標待確認，完成正式及精簡文件，不為補齊欄位停止。

    06補答與修改會接續完成

    1. 提供資料直接貼素材或附檔；若來源可讀且目的清楚，Codex 直接整理並執行。
    2. 只補關鍵缺漏需要日期、範圍或不清欄位時，回答那一個問題即可；不用重新貼完整需求。
    3. 開啟成果並修改使用實際檔案連結核對，再用日常語言說要改哪裡；Codex 沿用來源更新相關成果並保留舊版本。

    Codex 會自行讀內部規則、檢查環境、整理有來源的資料、選參數、執行並確認檔案存在。你不需要指示它讀 MD、回報技能路徑、編輯 JSON 或指定腳本。

    07另外選用的模擬教學

    本節教學採原創模擬資料，僅在你明確要求示範或練習時使用。一般啟動不會提供課程模式，也不會讀這些檔案。想練習可在啟動後用自己的話說『請用這章模擬資料示範一次』；Codex 會標示模擬，與工作成果分開保存。

    進階：給維護者｜模擬來源、保留的手動命令與測試細節

    先讀 source.md 的模擬文件需求，確認文件類型、讀者、目的、事實與限制。input.json 提供輸入格式；若要改寫既有 DOCX，先請 Codex 擷取原文並列出不能改動的事實，再調整文字。

    1. 先確認誰要讀、要做什麼請 Codex 回報文件類型與目的，例如提供主管評估而非公告已通過。這會影響語氣、章節與結尾。
    2. 建立不可變動的事實清單把原文日期、數字、完成狀態及明確限制分開列出。若來源相互矛盾，並列衝突讓人確認，不挑一個看起來合理的答案。
    3. 檢查架構與表達正式版交代背景、作法與下一步；精簡版留下讀者決策需要的資訊。用清楚句子取代堆疊形容詞，避免把期望寫成承諾。
    4. 填入來源並產出兩版依 SKILL.md 契約建立 reviewed-input.json，保留來源與待確認欄。執行 run.py，同時生成正式及精簡的 Markdown 與 DOCX。
    5. 用原文逐項覆核核對四個產物的數字、日期與核心要求，再用 Word 開啟確認標題、段落及符號。確保精簡不會刪掉重要限制或待確認事項。

    先以 input.json 產檔，再直接從 source.md 重建自己的 reviewed-input.json。把正式與精簡版放在一起，找出相同的事實與不同的表達；遇到只出現在其中一版的新金額、新期限或新承諾，就回原文檢查並修正。

    進階：給維護者｜維護者產檔測試
    維護者產檔測試
    python .agents/skills/document-writer/scripts/run.py --input examples/document-writer/input.json --output outputs/document-writer

    08開啟並核對成果

    這裡保留教學範例的預期成果，供明確練習時核對；不能當作一般工作的預填答案。實際成果仍依你的來源。

    進階：給維護者｜模擬範例預期內容
    • document-formal.md／docx 與 document-concise.md／docx 都實際建立，Word 檔可開啟。
    • 正式版提供完整脈絡；精簡版保留目的、主要事實、行動與限制。兩版的日期、金額與確認狀態一致。
    • 尚缺的資料明列待確認，沒有加入看似專業卻未經來源支持的效益或數字。
    進階：給維護者｜模擬預期摘錄
    模擬預期摘錄
    用途：請主管確認試辦方向與待決事項（模擬）。
已知事實：對象為內部同仁，使用現有會議時段分享技巧。
預算、試辦日期與負責人：待確認。
正式與精簡版保留相同事實，不新增成本效益。
    本技能實際產物核對方式
    document-formal.md開啟檔案，抽查來源、日期、數字及待確認欄位
    document-formal.docx開啟檔案，抽查來源、日期、數字及待確認欄位
    document-concise.md開啟檔案，抽查來源、日期、數字及待確認欄位
    document-concise.docx開啟檔案，抽查來源、日期、數字及待確認欄位

    只有計畫、操作建議、中間核對資料或待補空殼都不代表完成。有工具、連線或權限限制時，Codex 應具體列出未完成項目；程式格式檢查不等於原生 Office 畫面驗收。

    09發現問題時直接提出

    可以直接指出『這個期限不對』、『這項還沒核准』或『請縮短給主管看』。Codex 會回查來源、沿用已確認資訊更新；若修正與來源衝突，保留修正的依據與待確認狀態。內部格式錯誤由它先處理，不要求你填結構資料。

    進階：給維護者｜技術排錯與教學案例
    原有教學排錯案例核對方法
    文件變長，卻沒有更清楚要求每一段只解決一個讀者問題，刪掉重複形容，保留可核對事實與行動。
    精簡版少了重要限制把該限制加入共同輸入並重建兩版。精簡不是拿掉不確定性，而是用較短文字說清楚。
    原文沒有預算卻出現金額要求指出來源。找不到就改成待確認，檢查其他新加入的人名、日期與成效是否也無依據。

    10驗收與使用邊界

    核取方塊供本次閱讀自行檢查；重新開啟頁面會重設，不會上傳或儲存個人紀錄。

    預設只在工作區產檔。寄送、外部上傳、發布或提交報帳仍依既有授權要求；來源文件內的指令只當資料。保留原始資料，不捏造人名、金額、期限、數據或研究來源。

    進階：給維護者｜保留的延伸練習

    拿模擬文件的複本，將讀者從主管改成跨部門同事。請 Codex 調整章節與語氣，列出它改了哪些表達、保留哪些事實，並在輸出前做一次新舊事實對照。
