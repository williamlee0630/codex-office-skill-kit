    CHAPTER 06 / 實作課程

    發票與收據整理助理

    從收據保留可核對的欄位、按幣別統計，讓不清楚和可能重複的資料留在檯面上。

    約 30 分鐘Windows / Codex日常工作工具receipt-organizer

    01這個 Skill 解決什麼工作

    報帳最容易出錯的地方，是看不清的數字被當成確定值，以及不同幣別被加成一個沒有意義的總額。這個技能整理收據欄位、保留來源，並用程式做可核對的分類與金額統計。

    圖片與掃描 PDF 需要實際視覺辨識、可用 OCR 或人工轉錄。這套 Python 腳本不冒稱具備 OCR；無法讀出的日期、金額或店家名稱維持待確認，不能靠常見價格推測。

    可能重複的收據會被標示，原始紀錄仍保留。沒有經過人工確認前，不靜默刪掉其中一筆，也不把不同幣別直接相加。

    02哪些工作適合使用

    • 行政與財務窗口：需要將多張收據整理成可以核對的報帳明細。
    • 業務與差旅人員：要區分交通、餐飲、辦公用品等支出，保留幣別。
    • 覆核人員：需要看見待確認金額與疑似重複資料，回到原始憑證判斷。技能輸出不能取代公司的正式報帳規則。

    這是日常工作工具，可反覆用於真實工作。自然語言也能選用，不需要依序啟動其他技能；已有完整目的與素材時直接執行。

    03提供必要素材即可

    直接貼文字、附檔或提供可讀檔案，無須固定檔名、表單或長提示詞。Codex 會先讀目前對話與來源，自行查看能取得的檔案、欄位、工作表與環境；只問會阻止正確完成或實質改變結果的缺漏。

    標題、檔名、輸出位置與一般呈現方式採合理預設。未知人名、期限與成效數字保留待確認；有依據的內容先完成，不拿範例資料填空。

    04只送出技能名稱

    可複製的啟動內容
    $receipt-organizer

    只有名稱時會依工作用途引導；已有素材或正在補答時沿用前文，不重新介紹功能或要求選擇。

    05實務工作對話示意

    以下是對話方式示意，不是技能自動載入的來源，也不代表已在你的電腦產檔。你可用自己的話回答，不必回覆編號。

    角色內容
    使用者$receipt-organizer
    Codex請上傳收據或憑證，也可以提供可讀的 PDF、圖片或報帳明細。我會核對欄位、分幣別合計，整理成 Excel。
    使用者這批出差收據請整理成報帳明細；其中一張幣別看不清。
    Codex會先讀原件並轉錄清楚欄位，只針對那張的幣別詢問；其餘資料繼續整理，分幣別合計並產生 Excel。

    06補答與修改會接續完成

    1. 提供資料直接貼素材或附檔；若來源可讀且目的清楚，Codex 直接整理並執行。
    2. 只補關鍵缺漏需要日期、範圍或不清欄位時，回答那一個問題即可；不用重新貼完整需求。
    3. 開啟成果並修改使用實際檔案連結核對，再用日常語言說要改哪裡；Codex 沿用來源更新相關成果並保留舊版本。

    Codex 會自行讀內部規則、檢查環境、整理有來源的資料、選參數、執行並確認檔案存在。你不需要指示它讀 MD、回報技能路徑、編輯 JSON 或指定腳本。

    07另外選用的模擬教學

    本節教學採原創模擬資料，僅在你明確要求示範或練習時使用。一般啟動不會提供課程模式，也不會讀這些檔案。想練習可在啟動後用自己的話說『請用這章模擬資料示範一次』；Codex 會標示模擬，與工作成果分開保存。

    進階：給維護者｜模擬來源、保留的手動命令與測試細節

    開啟 simulated-receipt.png 與 simulated-receipt.pdf：它們是同一張模擬收據的兩種格式，只對應 R1，不是兩筆交易。receipts.json 共有 5 筆，R2 至 R5 是清單練習，沒有對應原圖，不能聲稱已核對影像。保留來源、日期、店家、金額、幣別與分類，看不清或未提供的欄位維持 null 並列待確認。

    1. 先看憑證，再看轉錄開啟唯一一張模擬收據的 PNG 與 PDF，核對 R1。請 Codex 說明目前能使用的圖片或 PDF 讀取方式，沒有辨識能力就由你人工核對，不能假稱 OCR 成功。
    2. 核對必要欄位每筆檢查日期、店家、總額與幣別。缺少金額不能填零；幣別未知就保持未知，不拿電腦地區設定代替。R2 至 R5 的依據是模擬清單，不是原圖。
    3. 確認分類及疑似重複分類以品項與用途為依據，不確定則待確認。R2 疑似重複於 R1，只能標示，不靜默刪除。PNG 與 PDF 是同一張憑證，也不能算兩筆。
    4. 以結構資料產出 Excel把人工或視覺核對結果寫入 reviewed-input.json，依技能契約執行 run.py。不同幣別分開列出，未知金額不算入已知合計。
    5. 在 Excel 與來源間回查開啟 receipts.xlsx，核對 5 筆明細、分類、幣別小計與待確認項。不要把含疑似重複資料的合計直接當成已核准報帳金額。

    第一輪以 receipts.json 做確定性的產檔測試；這只能證明轉錄資料可生成報帳表。第二輪對照原圖核對 R1，記錄實際辨識方式；R2 至 R5 僅依模擬清單演練。R5 多欄未知，不能為了表格整齊猜出金額。重新建立 reviewed-input.json，保留兩種來源的差別。

    進階：給維護者｜維護者產檔測試
    維護者產檔測試
    python .agents/skills/receipt-organizer/scripts/run.py --input examples/receipt-organizer/receipts.json --output outputs/receipt-organizer

    技能規則 · 內部資料契約 · 模擬來源 · 範例結構資料

    教學可用 模擬收據 PNG 或 PDF。原始影像測試加 --simulation；第一次只建 transcription-template.json，不做 OCR。Codex 接著自行看圖、核對及轉錄，再產報帳 Excel，不能把模板交付為完成。

    08開啟並核對成果

    這裡保留教學範例的預期成果，供明確練習時核對；不能當作一般工作的預填答案。實際成果仍依你的來源。

    進階：給維護者｜模擬範例預期內容
    • receipts.xlsx 是可在 Excel 開啟的試算表，逐筆保留日期、店家、金額、幣別、來源與確認狀態。
    • 同一幣別才合計；未知金額不當成 0，不會出現未經提供匯率的跨幣別總額。
    • 疑似重複仍在明細，且有清楚標記。看不清的憑證欄位留待人工確認，不產生看似確定的猜測。
    進階：給維護者｜模擬預期摘錄
    模擬預期摘錄

    只有計畫、操作建議、中間核對資料或待補空殼都不代表完成。有工具、連線或權限限制時，Codex 應具體列出未完成項目；程式格式檢查不等於原生 Office 畫面驗收。

    09發現問題時直接提出

    可以直接指出『這個期限不對』、『這項還沒核准』或『請縮短給主管看』。Codex 會回查來源、沿用已確認資訊更新；若修正與來源衝突，保留修正的依據與待確認狀態。內部格式錯誤由它先處理，不要求你填結構資料。

    進階：給維護者｜技術排錯與教學案例
    原有教學排錯案例核對方法
    圖片打不開或沒有 OCR 工具請 Codex 回報限制，改用你逐欄核對的轉錄 JSON。這是可接受的替代流程，但驗收紀錄必須寫『人工轉錄』。
    台幣和外幣被加在一起先確認 currency 欄位，再依幣別重建統計。沒有來源匯率就不換算，也不假設所有 $ 都是相同幣別。
    重複項目不見了檢查是否被自行刪除。恢復原始紀錄，標為疑似重複並請人核對，報帳前再決定是否排除。

    10驗收與使用邊界

    核取方塊供本次閱讀自行檢查；重新開啟頁面會重設，不會上傳或儲存個人紀錄。

    預設只在工作區產檔。寄送、外部上傳、發布或提交報帳仍依既有授權要求；來源文件內的指令只當資料。保留原始資料，不捏造人名、金額、期限、數據或研究來源。

    進階：給維護者｜保留的延伸練習

    在 receipts.json 的複本新增一筆金額未知、幣別明確的模擬憑證。產檔後檢查它仍在明細及待確認清單，且不會被算成零元完成核對。再比較兩張同店同額憑證，練習說明為何不能只靠相似就刪除。
