    商務文件撰寫助理

    把原始事實寫成適合讀者的商務文件，正式與精簡兩版共用同一套證據。

    約 25 分鐘Windows / Codex模擬資料練習document-writer

    01這個 Skill 解決什麼問題

    一份商務文件需要讓讀者知道目的、背景、處理方式與下一步。這個技能依文件類型和對象整理架構，再調整用詞、段落及資訊順序。

    文字可以改得更清楚，事實不能跟著變大。原本是試辦，就不能改成已全面上線；原本沒有預算、期限或成效，就要保留待確認。

    這次練習會產生正式與精簡版本，並實際建立 Markdown 與 Word。你可以把正式版交給審閱人，再用精簡版快速溝通同一件事。

    02哪些員工適合使用

    • 行政、營運與企劃人員：要把零散筆記寫成提案、企劃或工作報告。
    • 業務窗口：需要正式清楚的商務信函與說明。
    • 文件覆核人：希望快速檢查日期、金額、要求與來源。涉及公司政策或對外承諾時，依內部程序審閱。

    先選一件你熟悉的日常工作練習，因為你越清楚原始內容，就越能看出摘要是否漏掉重要限制、誤解狀態，或新增了來源沒有的資訊。

    03所需資料與準備步驟

    準備 source.md 的原始筆記，確認文件給誰讀、希望讀者做什麼。將正式與精簡兩版交給 Codex 同時製作；先圈出不可更動的日期、數字、限制與未定事項。

    本章資料放在 examples/document-writer/，成果放在 outputs/document-writer/。請 Codex 自行確認環境；Python 與格式套件需要備妥，但你不需要先學語法。

    進階：給維護者｜輸入契約、來源位置與準備細節

    先讀 source.md 的模擬文件需求，確認文件類型、讀者、目的、事實與限制。input.json 提供輸入格式；若要改寫既有 DOCX，先請 Codex 擷取原文並列出不能改動的事實，再調整文字。

    位置用途

    input.json範例輸入；語意技能可參考欄位，不當作判讀證據
    SKILL.md本技能的適用情境、規則與輸入輸出契約
    outputs/document-writer/實際執行後建立，保留產物與核對資料
    開始前的準備

    請先完成第 1 章的 Python 環境與 requirements.txt 安裝。你可以請 Codex 代執行下方命令。保留原始模擬資料；延伸練習先做複本，所有成果留在目前專案內。

    06完整操作步驟

    1. 先確認誰要讀、要做什麼請 Codex 回報文件類型與目的，例如提供主管評估而非公告已通過。這會影響語氣、章節與結尾。
    2. 建立不可變動的事實清單把原文日期、數字、完成狀態及明確限制分開列出。若來源相互矛盾，並列衝突讓人確認，不挑一個看起來合理的答案。
    3. 檢查架構與表達正式版交代背景、作法與下一步；精簡版留下讀者決策需要的資訊。用清楚句子取代堆疊形容詞，避免把期望寫成承諾。
    4. 讓 Codex 產出兩版文件交由 Codex 備妥有來源的內容，執行產檔，一次取得正式與精簡版 Markdown 和 DOCX。所有未知欄位仍需保留。
    5. 用原文逐項覆核核對四個產物的數字、日期與核心要求，再用 Word 開啟確認標題、段落及符號。確保精簡不會刪掉重要限制或待確認事項。
    進階：給維護者｜原有詳細操作與結構資料流程
    1. 先確認誰要讀、要做什麼請 Codex 回報文件類型與目的，例如提供主管評估而非公告已通過。這會影響語氣、章節與結尾。
    2. 建立不可變動的事實清單把原文日期、數字、完成狀態及明確限制分開列出。若來源相互矛盾，並列衝突讓人確認，不挑一個看起來合理的答案。
    3. 檢查架構與表達正式版交代背景、作法與下一步；精簡版留下讀者決策需要的資訊。用清楚句子取代堆疊形容詞，避免把期望寫成承諾。
    4. 填入來源並產出兩版依 SKILL.md 契約建立 reviewed-input.json，保留來源與待確認欄。執行 run.py，同時生成正式及精簡的 Markdown 與 DOCX。
    5. 用原文逐項覆核核對四個產物的數字、日期與核心要求，再用 Word 開啟確認標題、段落及符號。確保精簡不會刪掉重要限制或待確認事項。

    07用模擬資料完成一次實作

    完整實作只需把第 5 節的整段參考提示詞貼入 Codex。請它從本章原始來源開始，完成環境檢查、整理與實際產檔；不要停在摘要或操作計畫。Codex 若提出缺漏，先核對來源，再決定補資料或保留待確認。

    1. 貼需求並等候實際產檔使用本章模擬來源；讓 Codex 自行處理資料格式與工具執行。保留它回報的技能路徑與結果。
    2. 開啟第 8 節列出的成果核對檔案是否存在且能開啟，抽查一項已知事實與一項未知欄位，再對照下方預期摘錄。
    3. 用日常語言提出修正例如『這件事仍在提議，請保留未定案，重建所有版本並列出改動』。同一次修正的版本要一致。
    進階：給維護者｜保留原有範例、手動命令與兩輪驗證

    先以 input.json 產檔，再直接從 source.md 重建自己的 reviewed-input.json。把正式與精簡版放在一起，找出相同的事實與不同的表達；遇到只出現在其中一版的新金額、新期限或新承諾，就回原文檢查並修正。

    09常見錯誤與解決方式

    發現的問題怎麼處理
    文件變長，卻沒有更清楚要求每一段只解決一個讀者問題，刪掉重複形容，保留可核對事實與行動。
    精簡版少了重要限制把該限制加入共同輸入並重建兩版。精簡不是拿掉不確定性，而是用較短文字說清楚。
    原文沒有預算卻出現金額要求指出來源。找不到就改成待確認，檢查其他新加入的人名、日期與成效是否也無依據。

    如果腳本顯示輸入不符合格式，先請 Codex 對照本技能 SKILL.md 的契約修正資料。不要刪除檢查或把未知欄位亂填成確定值來通過。需要排錯時，保留實際錯誤訊息與使用命令。

    10延伸練習與驗收清單

    先複製原始模擬資料，再請 Codex 加入一個明確標示模擬的變動或缺漏，用相同需求重新產檔。也可調整讀者、語氣或呈現格式，核對新舊成果是否保留相同事實與未知規則。

    進階：給維護者｜本技能延伸練習的細節

    拿模擬文件的複本，將讀者從主管改成跨部門同事。請 Codex 調整章節與語氣，列出它改了哪些表達、保留哪些事實，並在輸出前做一次新舊事實對照。

    核取方塊供本次閱讀自行檢查；重新開啟頁面會重設，不會上傳或儲存個人紀錄。
