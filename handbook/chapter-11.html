    CHAPTER 11 / 實作課程

    資料研究與調查助理

    從可追查的來源比較觀點與資訊缺口，把文件說法、研究推論與未知分開。

    約 30 分鐘Windows / Codex模擬資料練習research-assistant

    01這個 Skill 解決什麼問題

    研究不只是把幾份文章摘要接起來。這個技能先確認研究問題，再對照各來源的時間、立場、支持證據與差異，整理目前能回答的範圍。

    同一個數字可能來自不同期間或不同定義。當文件衝突，保留兩邊說法與日期，指出尚未能確認的原因；不能選一個喜歡的答案當成真相。

    本套模擬練習可以完全以本機來源進行。無網路時明確標為離線研究；如果另外使用網路搜尋，必須記錄實際取得的來源、日期與限制，不能虛構網址或搜尋紀錄。

    02哪些員工適合使用

    • 企劃、產品與行政人員：需要針對明確問題比較多份資料。
    • 專案窗口：想知道現有文件已支持哪些結論、還缺哪些證據。
    • 主管與審閱人：需要從報告回到來源核對。對時效敏感的真實研究，還要確認資料是否仍適用。

    先選一件你熟悉的日常工作練習，因為你越清楚原始內容，就越能看出摘要是否漏掉重要限制、誤解狀態，或新增了來源沒有的資訊。

    03所需資料與準備步驟

    本次問題是『24 人部門訓練應優先確認哪個方案？』，資料基準日 2026-10-23。請 Codex 直接閱讀 sources/ 的兩份模擬方案做離線研究；你只需核對報告是否真的得到來源支持。

    本章資料放在 examples/research-assistant/，成果放在 outputs/research-assistant/。請 Codex 自行確認環境；Python 與格式套件需要備妥，但你不需要先學語法。

    進階：給維護者｜輸入契約、來源位置與準備細節

    先讀 input.json 中的研究問題與 sources 資料，並逐一開啟 sources/ 內的模擬 Markdown 來源。來源是教學文件，不是真實外部報導。記下文件名稱、日期、主張與限制；不能因為有檔名就當作已閱讀內容。

    位置用途
    examples/research-assistant/input.json本章練習來源；請先讀完整內容
    input.json範例輸入；語意技能可參考欄位，不當作判讀證據
    SKILL.md本技能的適用情境、規則與輸入輸出契約
    outputs/research-assistant/實際執行後建立，保留產物與核對資料
    開始前的準備

    請先完成第 1 章的 Python 環境與 requirements.txt 安裝。你可以請 Codex 代執行下方命令。保留原始模擬資料；延伸練習先做複本，所有成果留在目前專案內。

    必讀原始來源：模擬甲方案 S1 · 模擬乙方案 S2。input.json 是問題及整理契約，不能取代逐一讀原文。

    將 JSON 放到新位置時，來源路徑也要對上

    研究技能的 sources[].path 以輸入 JSON 所在資料夾為起點。若建立 outputs/research-assistant/reviewed-input.json，S1 路徑應為 ../../examples/research-assistant/sources/plan-a.md，S2 比照；也可請 Codex 使用目前來源的絕對路徑。摘錄必須逐字存在於原文，並另行核對是否支持主張。

    06完整操作步驟

    1. 固定研究問題與範圍告訴 Codex 本章問題、2026-10-23 基準日與離線範圍；要求它把題目拆成現有文件可回答的面向。
    2. 實際閱讀每個來源逐一開啟 sources/ 的文件，記下來源識別、日期、主要說法與限制。資料日期未知就明列，不用檔案修改時間代替發布日。
    3. 比較一致與衝突將同一面向的不同說法並列。檢查定義、涵蓋對象與時間是否相同，不直接把不相同口徑的數字當成矛盾或平均。
    4. 寫出有邊界的結論每個結論指向實際來源；綜合判斷標為推論。資料不足時列出缺口與下一步可查什麼，不補造研究發現。
    5. 取得報告並抽查引用交由 Codex 整理來源及實際產檔，開啟 research-report.md 與 sources.csv，抽查文件是否存在、日期是否適用、原文是否支持結論。
    進階：給維護者｜原有詳細操作與結構資料流程
    1. 固定研究問題與範圍先請 Codex 讀 input.json 回報問題、資料截止日與離線模式。把很大的題目拆成能由現有文件回答的幾個面向。
    2. 實際閱讀每個來源逐一開啟 sources/ 的文件，記下來源識別、日期、主要說法與限制。資料日期未知就明列，不用檔案修改時間代替發布日。
    3. 比較一致與衝突將同一面向的不同說法並列。檢查定義、涵蓋對象與時間是否相同，不直接把不相同口徑的數字當成矛盾或平均。
    4. 寫出有邊界的結論每個結論指向實際來源；綜合判斷標為推論。資料不足時列出缺口與下一步可查什麼，不補造研究發現。
    5. 產檔並抽查引用把整理結果寫成 reviewed-input.json，執行 run.py。打開 research-report.md 與 sources.csv，抽查每個結論所引用的文件是否存在且支持該句。

    07用模擬資料完成一次實作

    完整實作只需把第 5 節的整段參考提示詞貼入 Codex。請它從本章原始來源開始，完成環境檢查、整理與實際產檔；不要停在摘要或操作計畫。Codex 若提出缺漏，先核對來源，再決定補資料或保留待確認。

    1. 貼需求並等候實際產檔使用本章模擬來源；讓 Codex 自行處理資料格式與工具執行。保留它回報的技能路徑與結果。
    2. 開啟第 8 節列出的成果核對檔案是否存在且能開啟，抽查一項已知事實與一項未知欄位，再對照下方預期摘錄。
    3. 用日常語言提出修正例如『這件事仍在提議，請保留未定案，重建所有版本並列出改動』。同一次修正的版本要一致。
    進階：給維護者｜保留原有範例、手動命令與兩輪驗證

    先用 input.json 驗證產檔，再獨立閱讀 sources/ 裡的原始文件重新整理。挑一項一致觀點與一項不同說法，逐字找出支持位置。寫下這份報告無法回答的問題，避免把『沒有找到』寫成『不存在』。

    09常見錯誤與解決方式

    發現的問題怎麼處理
    報告引用了來源資料夾沒有的文章要求列出實際開啟路徑。無法證明取得的來源就移除，並重新檢查所有受影響結論。
    不同來源的數字被直接平均先比較定義、期間與對象。不可比較的數字應並列說明，不能靠平均掩蓋差異。
    離線報告寫成最新市場調查將模式明確改成『以現有模擬文件為基礎的離線研究』，交代資料日期與外部驗證缺口。

    如果腳本顯示輸入不符合格式，先請 Codex 對照本技能 SKILL.md 的契約修正資料。不要刪除檢查或把未知欄位亂填成確定值來通過。需要排錯時，保留實際錯誤訊息與使用命令。

    10延伸練習與驗收清單

    先複製原始模擬資料，再請 Codex 加入一個明確標示模擬的變動或缺漏，用相同需求重新產檔。也可調整讀者、語氣或呈現格式，核對新舊成果是否保留相同事實與未知規則。

    進階：給維護者｜本技能延伸練習的細節

    在 sources/ 複本加入一份日期未知、觀點不同的模擬備忘錄，重新做來源比較。檢查技能是否將它列為有限證據，並說明還需要查核什麼，而不是因為檔案較新就取代其他來源。

    核取方塊供本次閱讀自行檢查；重新開啟頁面會重設，不會上傳或儲存個人紀錄。
