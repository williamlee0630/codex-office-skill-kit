## 指示一致性與需要修正的地方

40 則下一回覆均能依新啟動規則寫出合理行為；未觀察到必須主動推送課程／範例模式、要求使用者操作腳本、填 JSON 或重新確認開始的指示。這是人工語意排演的結果，不是 40 次端到端成功數。

1. **建議修正示範文件的可複製命令。** meeting-assistant、project-tracker、weekly-report 的 demo.md 一方面要求「先讀原始資料，重新整理後產檔」，另一方面把 `--input <技能資料夾>/references/example.json` 作為主要命令。可依上下文理解成格式煙霧測試，不是不可調和衝突，但複製命令的代理或學員會跳過原始判讀。建議改成 Codex 從 source.md 自建的工作 JSON 路徑；保留 example.json 命令時明確標成「僅程式產檔測試，不算語意驗收」。此問題在本次沒有發生成果造假，因實際任務使用新原文與新 JSON。
2. **低優先文字一致性：email-assistant 工作流程第 1 步。** 「確認郵件範圍、基準日期與輸出位置」可能被誤讀為每次都向使用者發問，但 SKILL 開頭、輸入規則與 operation.md 明確指定合理預設、基準日不阻擋摘要與草稿。可改成「從需求／來源取得範圍，基準日可未知，輸出位置自行預設」，消除多餘提問誘惑。本次排演可依優先上下文解決，非阻斷缺陷。
3. **低優先示範驗收範圍：** meeting/project/weekly 的 demo.md 五項驗收共用「開啟 Markdown、DOCX、Excel」，但各技能實際產物不全含這三種 Office 格式。建議列各自真實產物，避免代理要求不存在的檔案。operation.md 與 SKILL 本身已正確要求檢查本技能實際產物。
4. **環境限制須誠實回報：** 本次實際 DOCX 生成及讀回成功，畫面版面尚未驗證。這是本機缺 soffice.exe 的具體限制，不是技能觸發失敗，也不是原始內容判讀失敗。不可把 14 項讀回檢查當成畫面驗證或已安裝 Codex 端到端驗收。
