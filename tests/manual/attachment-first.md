# 九個 Skill 的乾淨對話驗收

這是維護者驗收程序，不是學員操作要求。提示詞唯一來源為 handbook/experiences.py，網站由同一份資料生成；不要另外寫一段較容易成功的測試提示詞。

郵件章現改為 Gmail 主示範，需在有 Gmail 工具與有效帳號授權的乾淨對話實測；不得用貼上三封郵件的通過結果代替。測試真實信箱須有對應讀取授權，公開摘要不含原信個資，結果見 qa/gmail-demo-acceptance.md。

1. 各技能使用全新、彼此隔離的 Codex 對話與工作區，只安裝該技能完整資料夾；不帶入前一輪產物。
2. 只貼該章「立即體驗」原文，有附件時只附該章下載檔。PNG 使用實際圖像輸入；CLI 的非影像附件需放入空工作區，記錄這與桌面拖曳附件的差別。
3. 不提供已整理的 JSON、預期答案、原工具包 examples 或本機內部資料路徑。Codex 為本次資料自行建立的內部 JSON 可作為執行中間檔。
4. 保存原始 CLI JSONL 於未公開工作目錄。確認它實際讀取 SKILL.md，並檢查所有讀檔／執行事件；若讀到內附其他模擬來源，不能只依產檔存在認定來源隔離成功。
5. 確認最終回覆及回合完成事件、無阻擋性不必要追問、實際成果檔存在可解析。退出碼 0 不等於通過；逾時、只有大綱或中間模板分別記錄。
6. 人工對照原文，核對郵件兩種期限狀態、收據三品項與 TWD 370、簡報五頁與備註、SOP 五步及未知制度、銷售六筆合計 33,900 與商品欄限制、十案預算人力、研究名額與資料日期、合約原文定位、對帳六類與一對一。
7. 另以 Word、Excel、PowerPoint 或適當渲染工具開啟；檔案格式檢查、原生程式開檔、逐頁畫面與真實桌面 Codex 拖曳操作分別記錄。部分開檔時仍在產檔中，應待對話完成後取唯讀副本驗證。
8. 公開摘要僅含技能、提示詞雜湊、附件數、產物檔名、內容核對與限制；不公開原始事件、個人家目錄、憑證或工作機設定。
